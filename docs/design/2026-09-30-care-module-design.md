# 「调养」模块设计稿（原第 4 模块「公益」的替代）

**版本**：v1.0 初稿　**日期**：2026-09-30　**状态**：待确认，V1 页面已按本稿在测试环境落地

---

## 1. 背景与目标

原第 4 模块叫「公益」，内容是医院目录与就诊点评，名不副实，也和「问答 · 记录 · 分享」三个模块的气质不搭。

新的第 4 模块要做三件事：

1. 承接白癜风患者最关心的日常话题：食疗、补铜、维生素、防晒、记录工具。
2. 在这些话题里**有节制地**引入优质商品，完成商业转化，但不做成「货架」。
3. 和其它三个模块形成闭环：问答里问到 → 调养里看 → 记录里验证 → 分享里交流。

**原「找医院」内容**已确定归入「分享」模块，保持 `/hospitals` 路径不变，不与商品混在一起。对外名称暂用「找医院」，是否统一改为「就医经验」见 §9。

## 2. 模块命名

| 候选 | 结论 |
|---|---|
| **调养**（采用） | 两个字，与「问答 / 记录 / 分享」同风格；涵盖食、用、护；语义是「辅助日常」，不暗示治疗 |
| 养护 | 偏护肤，覆盖不到食材 |
| 良品 / 好物 | 商业意图过直白，像货架 |
| 生活 | 太泛，辨识度低 |

页面标题：**调养 · 白友生活馆**。副标题：**把日常过好：吃得稳、晒得对、记得准。**

路径：`/care`。底部导航图标：`ri-leaf-line`。

## 3. 设计原则

1. **先讲清楚，再给选择**。每个专题先有一段科普和证据等级，然后才是选购要点和商品。
2. **证据等级徽章是与普通货架的根本区别**。老实告诉用户「这个没被证明能治病，但它是好食材」，比夸大功效更能建立信任。
3. **绝不暗示治疗**。与项目百科 `diet.md` 保持同一口径：黑芝麻、黑豆等「不是治疗白癜风的药物」。
4. **推荐可解释**。每件商品都写「为什么推荐、怎么选、什么情况下不适合」。
5. **不收买点评**。医院点评与商品完全分离，不接医院广告。

## 4. 信息架构

```
调养（/care）
├─ 顶部：标题 + 一句话定位
├─ 合规条：不是治疗建议 / 推广内容会标注
├─ 专题导航（横向滑动 chip）：全部 · 食材 · 补铜 · 营养 · 防晒 · 记录工具
├─ 专题区 × 5（每个专题一个卡片区）
│   ├─ 标题 + 证据等级徽章
│   ├─ 科普段落（为什么有人关心它 / 目前证据到哪）
│   ├─ 怎么选（2–4 条选购要点）
│   ├─ 注意事项（适用人群、用量、与用药的关系）
│   └─ 好物卡片（名称 · 为什么推荐 · 选购要点 · CTA）
└─ 我的调养清单（想要 N 件，本机保存）
```

### 4.1 五个专题

| 专题 | 证据等级 | 内容要点 |
|---|---|---|
| 🍚 **日常食材** | 证据有限 | 黑芝麻、黑豆、核桃、黑花生、黑芝麻糊。定位是「均衡饮食的一部分」，不是「补黑色素」。选购看配料表、无额外添加糖 |
| 🥣 **补铜与餐具** | 证据有限 | 铜是酪氨酸酶的辅因子，但没有可靠证据表明用铜器能改善白癜风。铜碗勺筷需食品级、酸性食物不久放、不要过量。先确认是否真的缺铜，再谈补充 |
| 💊 **维生素与营养** | 遵医嘱 | 维 D、B12、叶酸等：缺乏时应纠正，补多少请遵医嘱；不要自行长期大剂量。商品仅展示「选购要点」，保健食品须有「蓝帽子」标识 |
| ☀️ **防晒与遮盖** | 有研究支持 | 白斑处更容易晒伤，防晒是有共识的日常护理。物理防晒、防晒衣帽、遮盖产品。需求强、复购高，是最适合先做的专题 |
| 📷 **记录工具** | 生活品质 | 与记录页联动：SubSkin 标定贴纸（颜色校正 + 尺寸 + 对齐）、365nm 紫外手机夹灯（仅作辅助观察，不用于诊断）。V1 为「规划中」，收集想要人数 |

### 4.2 证据等级徽章

| 徽章 | 含义 | 使用规则 |
|---|---|---|
| 🟢 有研究支持 | 有指南或研究支持 | 必须能给出依据 |
| 🟡 证据有限 | 民间常用，缺少直接疗效证据 | 文案必须出现「不是治疗」 |
| 🔵 遵医嘱 | 与用药或检查结果相关 | 必须出现「遵医嘱」，不展示剂量 |
| ⚪ 生活品质 | 与疗效无关，只是用着更好 | 不写任何功效 |

## 5. 与其它模块的联动（导流入口）

| 来源 | 触发 | 落点 |
|---|---|---|
| 问答 | 用户问「吃什么好 / 能不能补铜」。AI 先给有证据的回答，再挂「去调养看看」模块芯片 | `/care#topic` |
| 记录 | 记录完成后出「本周调养小贴士」卡；拍摄引导里推荐标定贴纸 | `/care#tools` |
| 体检解读 | 如维 D 偏低，引导到对应专题，不直接推商品 | `/care#nutrition` |
| 分享 | 带「食疗」话题的帖子关联对应专题 | `/care#food` |

> V1 仅落地模块本身与导航入口；问答芯片依赖 `site-modules.json` 关键词，后端需重启后生效；记录、体检、分享的站内导流列入下一期。

## 6. 商业模式分期

1. **MVP（当前）**：不上架真实商品。每件好物是一张「选购指南卡」，带「想要」按钮，收集真实需求信号（本机清单 + 埋点）。用数据决定先引入什么。
2. **联盟分销（CPS）**：接入京东联盟、淘宝联盟等。零库存验证转化。好物卡片增加「去购买」跳转，并带「推广」标识。
3. **严选自营**：对转化好的少量单品做严选，公开产地溯源和检测报告。首批可以是自有的标定贴纸和紫外夹灯。
4. **订阅**：月度调养食材盒或会员服务。

**为什么 MVP 不放假商品**：没有真实供应链和链接就放商品、价格、品牌，是在欺骗用户。先收需求，比先摆货更诚实，也更省钱。

## 7. 合规红线（设计约束）

| 风险 | 约束 |
|---|---|
| 广告法：宣称治疗或疗效 | 普通食品、铜器、用品**一律不写功效**；保健食品展示「蓝帽子」和「不能代替药物」 |
| 推广标识 | 有分销链接的商品卡右上角固定「推广」标签；AI 回答里的商品推荐同样标识 |
| 医疗器械 | 家用光疗仪需要资质，本期**不引入** |
| 点评独立性 | 医院点评和商品分区，不接医院广告、不做付费推荐位 |
| 个人信息 | 病情、体检数据用于个性化推荐前，必须单独取得同意（个人信息保护法）；V1 不做个性化 |
| 铜器安全 | 必须食品级；酸性食物不长时间接触；不宣传「补铜治白」 |

## 8. 数据与埋点

V1 为纯前端静态目录（`src/data/care-catalog.ts`），无后端、无数据库变更。

埋点（沿用 `trackClick`）：

| 事件 id | 含义 |
|---|---|
| `care_topic_open` | 点专题 chip |
| `care_item_want` / `care_item_unwant` | 点「想要」/ 取消 |
| `care_item_buy` | 点「去购买」（有链接后） |
| `care_wishlist_open` | 展开我的清单 |

**核心指标**：专题浏览率、「想要」点击率（按商品排序即为选品依据）、从问答进入调养的比例。
