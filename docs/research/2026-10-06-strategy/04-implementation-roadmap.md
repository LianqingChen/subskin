# 落地实施：12个月路线、工程规格与验收

起点：方案批准与资源到位后的M1；若2026-10月启动，则M1=2026-10月、M12=2027-09月。日期为排期建议，未假定医院已签约。

## 1. 实施原则与范围

首期预算80万元为基准、50–100万元可缩放。创始人兼产品/技术，约1名合同工程、兼职ML、合并运营/标注和项目医生；以顺序推进为主，不能把全部工作包当作多人全速并行。

不重建整个产品。首90天完成授权最小闭环、标准化记录、标注规范、知识样例与人工复诊服务；M4以后再规模化数据和模型。每个工作包包含文档、工程、权限和人工流程，不能只用“页面做完”验收。

## 5. 数据模型设计草案

在保留旧表和字段的基础上新增，不删列、不改患者历史。以下是设计，不是已建库。

| 模型 | 主要字段/关系 | 与现有资产衔接 |
|---|---|---|
| ConsentGrant/ConsentScope/ConsentEvent | purpose、subject/profile、object_id、机构/协议、有效期、文本版本、commercial_training、追加事件 | 兼容现有UserConsent；独立新用途，旧同意不自动提升 |
| ImageAsset/ImageDerivative | 受保护object_key、来源ID、sha256、坐标、变换、资产种类、授权引用 | 连接assessment/diary/PostImage；原存储路径无需立刻搬迁 |
| ClinicalReference | 诊断、方法、审核角色/资质、时间、资料充分性、活动窗口 | 可关联PatientProfile/visit与ImageLabel |
| AnnotationTask/AnnotationVersion/ReviewDecision | 标签字典、mask资产、独立标注者、参考、盲标与仲裁 | 复用ImageLabelAnnotation画布和版本导出 |
| DatasetRelease/DatasetMember | manifest_sha256、subject_split、成员版本、授权snapshot、用途、批准与失效 | 替代随时重新随机切分的训练导出 |
| ModelEvaluation/ModelApproval | dataset_release、代码/权重/配置hash、指标CI、范围、签字、发布状态 | 连接现有VasiModelVersion/Run，不静默激活 |
| KnowledgeSource/EvidenceClaim/ClaimCitation | 来源权利、PMID/DOI、适用人群、风险/结局、段落映射、版本 | 连接Document/EncyclopediaArticle/Revision |
| ResearchProtocol/Enrollment/InstitutionAccess | PI、伦理依据、纳排、项目同意、访问范围/到期、退出 | 连接当前医院资料，不将公共医院表当认证账户 |
| FollowupVisit/Outcome | 时间窗、治疗事实、参考结局、缺失、来源 | 复用TreatmentEvent，形成纵向引用 |
| WithdrawalJob/DeletionReceipt | 授权失效、受影响资产/数据集/模型、合作方状态、例外依据 | 补足当前删除服务的派生与外部回收 |

数据库只存元数据，mask不再无限写base64到大量行；新衍生资产可入私有存储。迁移旧mask需要版本/哈希/访问兼容，按专门工作包执行，不顺手批量改历史。

用明确的授权服务：`can_use(actor, purpose, object, protocol, time)`在API、worker、训练清单发布、下载、模型作业启动前执行；每次结果记录依据。不可只在前端隐藏按钮或只存一个`training_eligible`布尔值。

## 6. API边界草案

| 接口组（候选路径） | 作用 | 权限/关键行为 |
|---|---|---|
| `/api/data-consents`、`/{id}/withdraw` | 新增、查看、撤回对象/用途授权 | 本人/合法监护；明确purpose，追加事件 |
| `/api/contributions` | 提交选择的记录与用途、查看进度 | 仅本人资产；拒绝无有效授权对象 |
| `/api/assets/{id}/access` | 有期限、目的绑定的访问 | 本人/角色/协议/范围联合校验；缓存私有 |
| `/api/admin/annotation-tasks` | 分配、提交、审核、仲裁 | 资格和任务权限，测试盲标隔离 |
| `/api/admin/dataset-releases` | 申请、审核、发布/失效 | 数据负责人批准；固定manifest和撤回标记 |
| `/api/admin/model-evaluations`、`/approvals` | 实验报告、审核与候选状态 | 标注权限不等于全局发布权限 |
| `/api/knowledge/topics`、`/claims`、`/feedback` | 公开审核知识、反馈 | 私有源文本不外泄；引用版本 |
| `/api/research/protocols`、`/enrollments` | 公开项目和自愿报名 | 具体项目独立同意；不自动传输联系方式 |
| `/api/institution/authorized-records` | 查看指定患者资料 | 机构隔离、用途/到期、访问事件 |
| `/api/data-rights/jobs` | 查看撤回/删除执行状态 | 仅本人或数据负责人，工单不泄露内部路径 |

实际路径需与现有路由规范核对，不额外建立与UserConsent竞争的通用认证系统；只增加用途授权层。API与服务分层、类型明确、错误不泄露内部细节、后台作业幂等。

## 7. 验收矩阵

| 场景 | 必须观察的结果 | 方法 |
|---|---|---|
| 不参与贡献 | 能正常记录、看历史、基础导出 | 合成账号浏览器流程 |
| 只公开，不训练 | 公开对象可见；训练/研究导出拒绝 | 权限用例与清单检查 |
| 仅模型训练 | 不进入公共图库，不给机构默认查看 | worker/API与匿名访问检查 |
| 不同研究项目/机构 | 项目A看不到项目B和非授权患者 | 两机构测试账号和对象级断言 |
| 过期/撤回 | 待运行作业停止、签名链接拒绝、工单形成 | 队列/下载/恢复演练 |
| 坐标正确 | 旋转/镜像/缩放后mask仍与指定版本一致 | 合成EXIF与多尺寸图，不用真病例fixture |
| 未知医学标签 | 不填为确诊/稳定；保留审核来源 | 标签审核与导出检查 |
| 同受试者多图 | 只能出现在一个split；近重复人工复核 | manifest自动校验+受控质量检查 |
| 不可比图对 | 允许视觉浏览，禁止无依据的量化 | 光照/视野/尺度不同的合成样例 |
| 生成/装饰图 | 不进入临床训练/固定测试 | asset_kind白名单与验证器 |
| 知识引用 | 主张有支持、适用范围清楚、过时可见 | 200题测试+50题医生盲评 |
| 模型发布 | 未达批准保持候选；旧报告不变；可回退 | 隔离环境、版本和审批记录 |
| 账户删除 | 活跃副本、衍生文件、恢复后数据均按策略处理 | 合成资产全链路删除收据 |
| PWA跨设备 | 375/768/1024/1440，明暗、相机失败、离线、safe-area | 浏览器+真实手机抽测，SW/manifest/version检查 |

## 8. 模型研究验收草案

先冻结预期用途：例如成年人普通RGB面部/手部候选范围测量，仍需核对，不作确诊。固定测试与外部测试分别出报告。

- 正例分割：Dice点估计≥0.85、患者bootstrap95%下界≥0.80；占比MAE≤5个百分点、95%上界≤7。以上数值是草案：须先在SS-08测得人工参考的评分者间/内差异再冻结（见01方案6.4），人工参考本身不够稳定时，门槛要相应放宽或改为与人工一致性比较。
- 边界、阴性误检面积、漏检、小病灶、肤色/设备/照明分组另报；样本不足只报告样本数与区间，不作达标宣称。
- 纵向：同次重复拍摄占比差异、共同视野和配准成功/拒绝率；预设例如重复性MAE≤3个百分点作为探索值，需专家冻结可接受误差。
- 分类：仅达到足量临床参考和独立对照后预设敏感度/特异度门槛；首年不以小样本准确率承诺自动诊断。
- 知识：引用支持率≥95%、200题危险用药建议0个、未知/偏方适当回应；专家评价方法和争议必须保留。单次通过不等于所有场景永远安全。
- 使用：医生20次以上资料准备过程比较，探索目标节省中位时间≥30%；记录病例构成和人工辅助，不能宣称已做随机试验。

样本量示例：分类敏感度若期望0.90、95%误差±0.05，简单二项近似需要约139名独立阳性对象；这不含特异度、失访、多部位、聚类和分组要求。分割应按患者层面的误差/重复性和置信区间设计；由统计人员计算，不能用“1000图”代替1000名独立病例。

## 9. 数据运营与研究执行SOP

每周：采集质量拒绝原因、重复图、待标注、双标分歧、授权失效、编辑反馈。每月：覆盖矩阵、每张标注分钟、返工、有效纵向队列、问答回归、成本/现金。每季度：合同/伦理/许可复审、备份恢复、防篡改验证、机构实际使用和付款。

数据集发布前形成清单：用途和许可 → 每样本授权 → 去标识与角色 → 标签参考 → split/重复 → 冻结hash → 数据负责人审批 → 私有作业环境。评测前冻结指标与代码；测试输出不得用于反复调参。下一版本使用新训练数据，保留版本可比性和足够测试刷新规划。

第三方模型/标注服务：确认部署地点、供应商是否留存和训练、权限、日志、删除、合同和跨境路径。首期优先本地/境内部署或明确合规服务，不能仅以“API接口”判断患者图片未向第三方披露。

## 10. 部署与发布

所有前端/后端/配置改造先记录DEPLOY_LOG，再按项目工作流部署测试并核查。当前共享后端需要完成可审查实现与离线检查，并在启用前按项目说明确认其正式用户影响；数据库仅增量兼容。管理后台无独立staging时，先使用preview验证，不把构建视为无风险。

新增研究/训练隔离后端并不取消现有规则。正式部署必须由用户明确确认完整累计变化；从最近正式发布收集全部待发布项，全量同步，生产后同源重建测试。模型激活属于影响共享正式服务的发布操作，也必须纳入审批与日志。

本次方案只新增文档，不执行上述实施或部署。
