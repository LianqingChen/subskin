# 管理后台「规划档案」设计

日期：2026-09-20
状态：用户于2026-09-21确认，已实施并部署测试环境后台预览。

## 目标

管理员从管理后台独立入口清晰浏览过往 agent 研究、规划、设计、修改方案及执行记录。文档仍存放在仓库原位置；新增文件无需手工录入后台。

## 方案比较

1. 仅展示 docs/research：开发范围最小，但目前只有一项盈利模式研究的四份文档，无法覆盖历史方案。
2. 受保护的统一规划档案（推荐）：读取指定历史目录，按主题关联文档，支持搜索和阅读；不迁移文件，不需要数据库变更。
3. 完整项目管理系统：在线编辑、审批、任务分配与版本控制。维护成本高，超出本次查看历史规划的需求。

采用方案2。

## 内容范围

递归收录以下目录中的 Markdown：docs/research、hermes_plan、docs/specs、docs/plans、docs/design、docs/business、docs/reviews、docs/audits、docs/mvp、docs/superpowers。兼容仓库顶层 research（存在时）。补充根目录 DEPLOY_LOG.md 作为独立「部署记录」，以及明确列入清单的历史设计文档：docs/photo-upload-and-ai-kb-requirements.md、docs/upload-photo-ai-knowledgebase-design.md、docs/vitiligo_area_assessment_research_report.md、docs/MEDICAL_ENCYCLOPEDIA_DESIGN.md、docs/EDITOR_DECISION.md、docs/NOTEBOOK_RESEARCH.md、PROJECT_FRAMEWORK.md。

不扫描任意用户指定目录，不收录上传目录、数据库、环境文件、归档压缩包、图片或日志。目录名和角色不是实际作者证据，不推断由哪个模型或agent编写。

## 页面与交互

- 入口：后台侧栏「规划档案」；手机从现有「更多」菜单进入；哈希路由 /#/planning。
- 页头：文档数量、主题数量、最近更新、刷新按钮。数字从可读取的真实文档计算。
- 左侧：全部、研究分析、设计方案、任务计划、发现与进度、验收审查、部署记录；桌面可折叠，手机为筛选抽屉。
- 列表：默认按文档日期倒序；显示主题、中文标题、日期、来源目录、文档种类、原文提取的短摘要。
- 搜索：标题、主题、相对路径及正文；支持分类、来源和月份筛选；结果分页。搜索失败与无结果分别显示。
- 阅读：桌面列表与正文并列，可收起列表专注阅读；手机由列表进入全文，并可返回保留筛选和位置。
- 正文：标题、段落、表格、列表、任务框、代码块、可点击章节目录；Markdown原文视图可切换。大表格与代码只在各自容器横向滚动。
- 同主题文档：在阅读区展示「方案 / 计划 / 发现 / 进度 / 验收」的实际关联文件。不存在的阶段不显示为已完成。
- 支持复制文档页面链接；文档选择及筛选反映在路由query，刷新仍可定位。只通过管理员API读取内容。

## 主题、日期与历史真实性

- 日期优先使用可信frontmatter或文件/父目录中的YYYY-MM-DD；无法提取时明确标识「文档日期未知」，文件更新时间单独展示。
- 同一主题文件夹内的 task_plan/findings/progress/assessment/design/verification 等自动聚合；扁平历史目录只去除已知阶段后缀，保留日期及剩余主题名，避免不同日期误合并。
- 明确区分「文档阶段」与「实际部署」。不根据文件名、checkbox或过期进度自动宣布正式上线。
- 本次展示仓库当前保留下来的历史文档。同一文件被覆盖前的内容、已删除文件和没有记录的方案无法自动还原；不承诺逐次Git版本回放。
- 标题和摘要来自原文规则提取，不调用LLM改写历史结论。

## 后端与数据安全

新增只读service以及 /api/admin/planning 下的列表、筛选信息和详情端点，统一依赖 get_admin_user。服务层不依赖FastAPI；API负责参数校验和异常映射。用户不可写入或执行文档内容。

采用固定目录允许清单、仓库相对标识、规范路径校验，拒绝绝对路径、目录穿越、符号链接和清单外文件。列表与详情复用相同边界。限制分页和文件大小，对不可读/超限文档给出明确提示，避免静默漏收录。文件缓存基于修改时间且有过期时间，点击刷新重新扫描。

响应标记 private/no-store。文档正文不写入前端构建产物、公共目录或本地持久缓存。识别到的凭据和个人联系方式脱敏后用于正文、摘要和搜索，原始内容不输出日志。Markdown禁用原生HTML执行，阻止危险协议、嵌入与自动外链图片；外部来源链接由管理员主动打开，本地关联文档走档案路由。

无需修改数据库、患者数据、公开问答导航或现有业务API契约。

## 代码结构

后端：独立规划文档service、管理员API路由、路由注册、服务与权限测试。
前端：PlanningArchive页面、筛选/列表/阅读组件、usePlanningArchive组合函数、planning API与类型；仅向现有后台导航添加一项。复用Naive UI与现有深色主题，不把主站布局搬入后台。按架构技能限制组件行数。

## 验收

1. 盈利模式研究可从「规划档案」找到，四份文档归属同一主题；早期hermes_plan与docs目录方案均能浏览。
2. 后续新增Markdown经刷新进入索引，修改文件显示新内容；文档删除后链接明确显示不可用。
3. 搜索正文关键词、来源/月份/类别筛选、分页、深链接与返回列表有效。
4. 普通用户和未登录访问API均被拒绝；目录穿越、符号链接、危险Markdown、敏感字段和超限文件具有针对性测试。
5. 请求竞态不覆盖当前选择；401/403时清空已加载档案状态，显示重新登录/无权限提示。
6. 管理后台类型检查与构建通过；375、768、1024、1440宽度可搜索和阅读，无页面横向溢出。
7. 归档只读；公开构建内没有文档正文；共享后端health正常。

## 部署与确认范围

遵循本轮用户提供的staging-first要求及近期已有admin-preview流程：使用独立web/admin构建，显式指定 /admin-preview/ base及staging下专用子目录，避免默认配置直接覆盖正式管理站。需要刷新主站staging版本时先记录DEPLOY_LOG，主站构建完成后再放置独立admin-preview，保留两应用隔离。

⚠️ 后端修改会立即影响所有正式环境用户。这里具体指共享服务将新增管理员只读接口并重启，可能出现短暂请求中断；本批不做数据库变更，不改患者业务行为。设计确认同时请求授权完成并经测试启用这一明确范围的后端更新。

交付测试入口：https://staging.subskin.cn/admin-preview/#/planning 。正式前端和正式管理站发布仍待用户验收后的明确指令。
