# 发现与调养：内容社区与电商式选购页重新规划

日期：2026-10-02。状态：用户已确认并开始实施；部署与验收状态见 DEPLOY_LOG.md。

## 1. 定位与范围

发现 `/community` 是病友的生活与经验内容流，不是商城的营销入口。调养 `/care` 是日常用品的选购入口，遵循电商的信息组织，但不虚构站内交易能力。

本次将“不需要显性种草、科普等”理解为：移除发现首页的显性频道入口和导购包装，不删除已有知识、病友帖子或旧链接。科学依据与使用风险保留在选购详情的必要位置。不是把发现也改成电商。

目标用户需要快速找到经验、降低护理选择成本，同时不因病情焦虑被诱导购买。界面用现有 primary 配色、RemixIcon、暗色模式和 PWA 导航；不引入新的 UI 框架。

## 2. 现状依据

- `CommunityPage.vue:38–43,462–481`：发现首屏三张频道卡为科普、种草、找医院，先于内容流展示。
- `CarePage.vue:60–90`：两个提示板块、分类栏、重复分类分段和逐段“看科普”链接共同争夺首屏。
- `CarePage.vue:75–87`：手机左栏固定 84px，余下空间仍放两列卡片；桌面分类栏目前 w-44。
- `ProductCard.vue:14–32`：分类图标占位图、理由、证据徽章、价格待定、32px 数量按钮挤在同一卡片。
- `care-catalog.ts`：5 类、15 个条目（5 食材、3 餐具、2 营养、3 防晒遮盖、2 规划工具）；没有真实品牌、商品图、价格、规格或购买链接。
- `CartSheet.vue` 与 `useCareCart.ts`：本机清单、数量和外部购买入口；没有订单、支付、库存、售后或跨设备同步。
- `site-modules.json` 是现有主导航事实来源，主导航为问答、记录、发现、调养；不按旧文档名称重命名。

## 4. 三种方向比较

1. **仅换标签**：把科普、种草改为指南、好物。改动小，但入口与页面职责仍重复，不推荐。
2. **内容社区 + 清晰选购页（推荐）**：发现集中内容，调养集中搜索、分类和选购；知识在需要时阅读。符合用户要求，能用现有数据先完成。
3. **完整交易商城**：品牌、SKU、库存、订单、支付、售后全部接入。长期可行，但当前没有商品与交易能力，不属于本轮排版范围。

## 5. 发现页设计

### 首屏与内容顺序
1. 紧凑工具区：关注 / 推荐 / 同城，搜索和排序为工具；沿用当前默认推荐，不改变推荐算法。
2. 内容瀑布流：封面或摘要、标题、作者、必要的互动信息。手机两列；桌面随容器增加列数。
3. 就医经验保留为轻量文字入口，桌面可置于工具区右侧，手机置于二级更多入口，不再占独立宣传卡片。
4. 发布入口延续现有浮动按钮，避开 BottomNav 和安全区；登录行为保持一致。

```text
关注  推荐  同城                 搜索 / 排序 / 就医经验
┌───────────────┐  ┌───────────────┐
│ 病友内容       │  │ 病友内容       │
│ 标题 / 作者    │  │ 标题 / 作者    │
└───────────────┘  └───────────────┘
                     发布入口
```

移除首屏科普、种草入口，不新增“精选种草”“热门好物”替代物。普通护理讨论可作为真实病友内容自然出现；商业合作必须独立标注，不能伪装普通经验。私密日记只保持现有本人可见逻辑，不扩大公开范围。

首期不新增生活/护理/就医等硬编码主题频道：当前搜索传的是 tag，需先确认真实标签、内容量和筛选语义。否则按钮看似分类，实际找不到内容。

旧 `/discover/science`、`/discover/picks` 暂保留兼容访问，不突然删除或重定向；知识页从商品详情按需进入。旧种草页退出主浏览路径，不继续作为核心频道宣传。

## 6. 调养列表设计

### 信息结构
1. 紧凑页头：调养标题、搜索、购物清单入口。
2. 简短交易状态说明：目前为选购参考，未接入购买；不在站内收款。无长宣传 banner、无自动轮播。
3. 分类：全部 / 防晒与遮盖 / 日常食材 / 维生素与营养 / 日常餐具 / 记录工具。分类 id 不变，防晒靠前，不称铜器为“补铜”用品。
4. 结果工具条：当前分类、结果数量、排序、已选条件清除。
5. 单一商品网格，取消全部分类下的重复分段与“看科普”横跳。
6. 页面底部简短说明；关键风险仍在详情购买动作之前可见，不能仅靠页脚免责声明。

### 手机
```text
调养                           购物清单(数量)
[搜索用品或名称                              ]
全部  防晒遮盖  食材  营养  餐具  记录工具 →
全部用品 · 15 项                      默认排序
┌─────────────────┐ ┌─────────────────┐
│ 图 / 品类占位    │ │ 图 / 品类占位    │
│ 名称            │ │ 名称            │
│ 状态 / 查看详情  │ │ 状态 / 查看详情  │
└─────────────────┘ └─────────────────┘
                       主导航保持原有位置
```
手机移除左侧分类栏，用可横滑分类行；列表占满内容宽度。375px 下两列卡片优先展示和详情入口，数量编辑放清单，不让三个44px控件挤进窄卡片。

### 桌面与平板
统一 max-w-6xl；md 以上左侧可折叠 w-52 分类，右侧工具条与网格，遵守现有页内导航规范。768px 保留舒适两列，不强求三列；1024px 按可用宽度三列，1440px 四列。手机分类与桌面分类共享状态；保留 `/care#food` 等深链接。

### 排序与筛选
首期仅默认排序和名称排序；默认把规划工具放后，不宣称“推荐算法”。真实价格接入后才提供价格升降序，并将未定价条目排后。没有销售/发布时间数据，不展示销量、评价、新品排序或品牌筛选。

## 7. 卡片、详情与清单

### 卡片
- 核心：统一图片区域 → 名称 → 真实规格（存在才显示）→ 价格或准确状态 → 一个主要动作。
- 当前通用品类显示“选购参考 / 查看详情”，不是每张都显示“价格待定”的假商品；规划工具明确“筹备中”。
- 有真实价格时显示价格，有有效 buyUrl 才显示外部购买；商业关系另行标识，不能弱化推广披露。
- 图片字段与真实素材作为后续数据补齐项；当前占位明确是品类图标，不生成假品牌包装，不借用无授权商家图。
- 长理由、完整选购要点、证据说明移至详情。高风险品类保留简短“先检查，遵医嘱”，不能为减少噪声隐藏风险。

### 详情
上方是图片区 + 名称、状态、真实规格价格和动作；下方为选购要点、使用注意和相关用品。移动端底部操作栏避开 BottomNav，桌面右栏内操作。

当前动作是“加入清单 / 查看选购要点”；有购买链接时“去商家购买”，明示跳转外部、不由 SubSkin 履约。通用品类不能用“立即购买”。知识参考作为详情的低层级入口，不再强迫回发现首页。

证据等级必须标明是“护理做法的依据”，不能把类别支持误当作某件商品疗效背书。餐具不宣传补铜或复色，营养品先检查与医嘱，365nm 工具不是家用诊断或治疗设备，规划阶段不提供购买。

### 购物清单
当前显示“购物清单”，说明仅存此设备，不冒充订单或云端需求登记；保持原 localStorage 键与账号隔离，不清空或迁移用户数据。

支持查看、数量、移除；不显示无意义的待定合计和结算按钮。未来有标价商品时显示“已标价条目参考合计”，未标价数量单独标明；去商家购买逐项跳转。

## 8. 实施边界与验收

设计确认后分两批实施并先部署 staging：
1. 发现移除宣传入口；调养列表扁平化、响应式分类、卡片状态整理。
2. 详情与清单术语/层级统一、路由兼容、AI 导航描述同步与验证。

涉及文件：CommunityPage.vue、CarePage.vue、ProductCard.vue、CareProductPage.vue、CartSheet.vue、CartButton.vue、care-catalog.ts、site-modules.json；必要时 useMainNav.ts/page-names.ts。复杂社区状态拆为 composable，避免继续扩大已632行的 View；不改社区推荐逻辑。

共享导航配置虽为 JSON，但后端会读取，需验证问答不再主动引导种草频道。若必须修改或重启共享后端，先单独提示影响所有环境；本轮设计不授权后端变更。

验收：
- 发现首屏没有科普、种草宣传卡，不破坏关注、同城、搜索、排序、帖子互动和发布。
- 15 条选购参考可检索、可分类，类别数量来自数据；没有假价格、销量、库存或订单。
- 分类、搜索、排序叠加正确，清除筛选、空结果、旧哈希/路由和详情返回正常。
- 老清单内容完整保留；未购买条目不显示结算/购买成功/需求提交成功等虚假状态。
- 375/768/1024/1440px 无溢出，按钮最小44px，暗色模式与安全区完整。
- 类型检查、相关测试、staging 构建通过，version/manifest/SW/health 核验并记录 DEPLOY_LOG。
- 正式环境必须在用户测试确认后完整同步，不能自动上线。
