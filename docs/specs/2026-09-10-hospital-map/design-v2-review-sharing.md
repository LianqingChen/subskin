# 医评（/hospitals）· 第二版设计：地图置顶 + 公开评价分享

> 首版见同目录 `design.md`（纯前端体验版、本机草稿）。本文件记录 2026-09-10 按用户需求改造后的形态。
> 需求原文：导航名改成 2 个字、一眼看出是医院/医生/治疗方案的评价与分享；地图放到顶端；用户先创建或选择医院（省份、城市、具体地址）；然后在下方评价和分享。
> 用户已确认：**要做真正公开可看的评价**（授权共享后端变更）。

## 命名
- 模块名：**医评**（2 字）。导航（AppHeader / BottomNav）、页面标题、router meta、`page-names.json`、AI 提示词模块表全部派生自 `web/shared/site-modules.json`。
- 旧名「就医地图」保留为 **legacy 关键词**（`site-modules.json` keywords + `rag.py SITE_FEATURE_KEYWORDS`），用户用旧名提问仍能导航到 `/hospitals`。

## 页面结构（自上而下）
1. **地图（顶端，全宽）**：全国省份分布，点省份筛选、点城市圆点筛选；当前选中医院所在城市的圆点放大；城市快捷筛选条带评价数。
2. **第一步 · 选择或创建医院**：省份 → 城市 → 区县/院区（自由输入 + datalist 联想）+ 名称/具体地址关键词 + 诊疗服务；结果卡片显示来源徽标（平台收录 · 附官方来源 / 病友补充 · 待核实）、评价数与评分；空结果引导「创建这家医院」。
3. **第二步 · 评价与分享**：Tab（综合 / 医院评价 / 医生评价 / 治疗方案 / 治疗经历）+ 评分与条数汇总 + 公开评价列表（分页「加载更多」）+ 写评价（未登录先弹登录）+ 我的评价（可删除）。
4. 对比（≤3 家）、想去/去过本机标记、信息纠错本机草稿、旧经历草稿「一键带入公开评价」。
5. 页脚：本机记录说明 + 内容来源与免责声明。

## 数据与合规
- 表：`hospitals`（origin: official/community；status: visible/hidden；省/市/区/详细地址/经纬度/官方来源）、`hospital_reviews`（target 四类；医生仅称呼+职称+科室；ratings JSON 与 outcome 自述分列；moderation_status: approved/flagged/blocked；软删除 status=deleted）。**全部 additive，无既有表结构变更。**
- 公开可见性：`status=visible` 且 `moderation_status != blocked`；未登录可读，发布需登录 + 写限速 + 封禁/禁言校验。
- 隐私：发布前 PII 检测（手机号/邮箱/身份证/银行卡）→ 命中即自动脱敏；用户显式确认保留原文则另留审计；医生不记录联系方式；公开分享写 `AuditLog`（target_type=hospital_review）。
- 医疗合规：疗效自述与主观评分分离展示；夸大疗效用语命中 → `flagged`（仍公开但标注「含疗效表述 · 待复核」）；LLM 内容安全审核异步执行，高危自动 `blocked` 下架；全站声明「本文不构成医疗建议」「个人经历不代表疗效」。
- 病友补充医院立即可见但强制标注「病友补充 · 待核实」，并留管理员下架接口（`/api/hospitals/admin/...`）。

## 验收
- 后端：18 项回归（服务层 10 + API 8）通过，覆盖幂等入库、目录筛选、创建医院、发布校验、PII 脱敏、夸大用语标记、屏蔽/软删可见性、统计聚合、鉴权与权限边界。
- 前端：`vue-tsc` 通过；staging 构建 + 375px / 1280px / 暗色模式浏览器实测（地图置顶、选择医院联动、登录拦截、创建医院弹窗、评价 Tab 与空态）。
- 未做（后续阶段）：精确院区坐标与导航、评价「有用」投票、举报与追评、管理后台评价审核界面。
