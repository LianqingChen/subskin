# 公益页重构设计（待用户批准）

日期：2026-09-16

## 目标与范围
让白癜风病友能按地点找到有来源依据的医院、阅读和分享亲身就诊经验，并理解常见治疗方式。提供可解释的评价和排序，不把体验数据包装成疗效、医疗实力或平台推荐。

## 现状
- `/hospitals` 把地图、写评价入口、医院选择器和评价板纵向叠放，查找与阅读需要来回滚动。
- `HospitalMap.vue` 是 ECharts 省界图，城市圆点为 44/54px；虽然有缩放，不能展示道路与院区。
- 后端种子目录和离线目录都用过城市中心经纬度，不能直接当成医院定位。
- 已有医院补充、医院详情、经验发布、六维体验分布、私有凭证图、举报、申诉、分享同意及审计功能。保留并核验这些流程。
- 六维为挂号与预约、候诊与流程、医患沟通、费用与告知、复诊与连续性、环境与隐私。
- 当前统计是条数聚合，没有排名所需的独立贡献者数及时间窗口；旧 ratingAvg 不再用于公开展示。
- 现有社区公约明确写着不做排名，若引入体验排序必须同步更新公约、页面说明与统计口径。

## 方案比较
| 方案 | 好处 | 限制 |
| --- | --- | --- |
| 只改现有省界图 | 工作量小、离线可用 | 无道路、院区搜索与真实导航，不能完成核心目标 |
| 真实地图 + 医院目录 + 经验互助（推荐） | 找地点、读经验、贡献经验形成完整流程 | 需要地图授权配置、院区核验、可靠聚合接口 |
| 做全国医院综合排行榜 | 易于传播 | 小样本误导、刷榜、医疗推荐风险高，不建议 |

## 页面布局
主导航继续叫「公益」，页内标题「找医院，看病友经验」。保留 max-w-6xl 容器。

桌面：可收起的 208px 左侧页内导航（找医院 / 病友经验 / 评价说明）；找医院区域顶部搜索与筛选，下面医院列表和地图并排，选中项双向联动。375px 手机：紧凑搜索、城市筛选、列表/地图切换；点地图标记打开底部医院卡，不让地图挤占全部页面。768/1024px 自动适配，避免同时堆三列。

首屏主动作「找医院」，次动作「分享就诊经历」。取消多个重复写评价横幅。治疗知识通过独立页面进入。

## 找医院与真实地图
- 优先高德 JSAPI 正规底图，参考其搜索框、位置图钉、地图工具条与列表联动习惯，不复制品牌视觉。
- 支持拖拽、滚轮/双指缩放、放大缩小按钮、重置、城市切换；用户主动点击后才申请当前位置。
- 搜索分为目录搜索（医院/城市/区县）与位置搜索（地点/地址）。位置搜索只移动地图或设搜索中心，高德 POI 本身不等于经过核验的白癜风医院。
- 全国低缩放展示小型数量聚合标记，点击放大展开；高缩放使用独立院区图钉，同坐标项展开列表；不再把大圆圈覆盖在全国省界上。
- 医院列表选择后聚焦对应院区；点图钉后高亮列表并显示院区、地址、来源核验日期、经验条数和「看详情」。路线路径仅在位置详情中进入地图导航，不混入科普正文。
- 坐标需含来源、坐标系、院区名与核验日期；历史城市中心坐标禁止用作精确图钉或附近距离计算。优先用官方院区地址与高德 POI 交叉核对，歧义时显示「院区位置待核实」。
- 首批核实现有收录医院；面向各地提供城市选择、空结果说明与补充入口，不宣称已覆盖全国全部医院。病友补充条目标注待核实。
- 展示官方科室信息所支持的白癜风诊疗项目；不因「有皮肤科」就自动认定所有治疗均可开展。
- 保留地图版权、审图号。地图未配置、授权失败、配额耗尽、离线时明确提示并提供可用目录，不把模拟地图当真实地图交付。
- 当前未发现项目内高德配置。需要项目所有者配置应用 key、安全密钥、域名白名单及服务使用授权；凭据不写入文档/聊天/仓库。JS 安全密钥走服务端代理。
- 地图隐私说明覆盖第三方 SDK 数据处理；位置不落库、不写分析事件。拒绝定位仍可手动搜索。

## 病友经验
- 浏览入口支持跨医院经验流，并保留当前医院过滤；按最新/有帮助排序。
- 清晰呈现医院、就诊月份、治疗方式（自述）、时间投入、费用说明、就诊流程、困难和经验。费用需注明单次/阶段/总计口径；个人费用不冒充医院报价。
- 写经验先选择医院，正文提示「这次做了什么 / 遇到了什么 / 下次会怎么准备」；已有六维体验可选填，并保留「没体验过」。
- 用「就诊提醒」组织可核对的事实，如费用是否提前告知、复诊如何安排；不生成黑榜，不把个体指控概括成医院事实。
- 用户可保留负面亲身经历；审核依据隐私、广告、侮辱或无依据的结论等风险，不因评价负面而屏蔽。
- 复用现有独立健康信息公开同意、私有凭证、删除、举报、申诉及审计链路。上传凭证不等于平台核实经历。非本人健康信息不公开。

## 治疗知识
- 独立页面介绍常见治疗类别、通常需要医生评估的因素、时间与复诊负担、就诊时可问的问题、资料来源和更新时间。
- 分类准备涵盖外用药、光疗、系统治疗、适用于特定人群的手术及支持照护。具体药品适应证和国内获批状态在内容实施时逐项查证，不以海外信息直接替代国内适应证。
- 不提供个体剂量/照射参数、不承诺疗效；正文显示「本文不构成医疗建议」。科普页面不放医院推荐、相应医疗服务跳转或购买链接。
- 病友使用过的方案属于个人经历，不因频次较高就冠名「主流」或「有效」。通用科普与病友经历明确区分。

## 评价与排名规则（产品提案，非法律认可结论）
1. 默认结果按地理/搜索匹配浏览；用户主动选择「经验较多」「单项体验排序」；不做全国综合实力榜、金牌医院或平台推荐勋章。
2. 保留六维分布，支持按某一个体验维度排序，不把疗效、治愈率、医术加入评分，不将六维强行合成医疗水平总分。
3. 单项排序建议采用最近 12 个月、每账号每院区取最近一条符合条件的评价。只计审核通过且已过冷处理窗口的数据；独立评价者达到 20 人且该维度有有效回答才具备比较基础。
4. 更严格的具体门槛：每个参与排序的维度本身需至少 20 个独立回答；「没体验过」不参与分母；阈值是平台初始产品规则，不是法定标准或统计保证。
5. 按满意比例的 95% Wilson 下界降序（满意为 1，一般/不满意为 0），减少小样本 100% 满意占榜。相同结果并列；排序指标名为「体验排序参考值」，不包装成医院星级。展示完整分布、样本量、窗口、截至时间和算法说明。
6. 未达门槛的医院显示「样本不足，暂不参与体验排序」，仍可查地址和经验。无数据不填零分。距离只对已核实院区计算并标注直线距离。
7. 作者删除、申诉下架、审核状态变化后重新聚合；同一人重复发帖不能增加独立人数。点赞不计医院体验分。
8. 不售卖名次、不接受付费删评或置顶；异常刷评、机构利益关联、内容纠错和申诉处理需留痕。上线规则须准确反映实际已实现的能力。
9. 法律风险不能靠「非广告」声明消除。面向正式环境启用体验名次前，应结合实际页面、机构关系与运营模式作法律审阅；设计与技术保护不等于零风险。

## 技术与实施顺序
- 前端拆分探索布局、真实地图、地图加载 composable、位置搜索、经验流与评价说明；View 不直接调用 API；遵守组件行数限制。
- 科普独立路由，目录复用既有 /hospitals；兼容 hospital/write/from 深链接与当前草稿、收藏。
- 后端需要准确院区坐标来源，以及按独立用户/时间窗口/审核状态聚合的 additive API；不复用历史平均星分伪装新排名。先测试再重启共享服务。
- 高德安全代理涉及 nginx 配置；上线前阅读相应技能，限制代理用途，不做通用任意 URL 转发。
- 若凭据尚未提供，可完成目录、经验、评价展示与地图适配器验证，但真实地图未接通时不得宣称完整完成。
- 不自动重启共享后端：依据 AGENTS.md，实施前明确「后端修改会立即影响所有正式环境用户」并取得涉及上线动作的确认。先准备完整、可审阅的改动及测试证据。
- 设计批准后进入实现；前端变更按要求记录 DEPLOY_LOG 后立即构建部署 staging。生产必须等用户测试并明确授权完整同步。

## 验收
- 375/768/1024/1440px、明暗主题、44px 点击区、键盘焦点、手机安全区与 BottomNav 正常。
- 地点搜索、目录过滤、地图缩放、图钉与列表联动、同坐标院区、定位拒绝、SDK 失败和离线目录均有可验证结果。
- 未核实坐标不会出现假精确定位或距离；无来源不显示支持某治疗；无评价不生成评分。
- 发布/编辑相关路径保持授权和隐私；读经验无需登录，发布需要登录，举报/申诉可达。
- 聚合测试覆盖 19/20 人门槛、重复用户、时间窗口、没体验过、待审/删除/受限评价、并列与异常样本。
- vue-tsc、构建、后端针对性测试通过；核查 staging version.json、health、manifest 与 sw.js，记录部署时间。

## 设计自审
- 已区分真实院区坐标与城市中心；没有借用旧坐标作导航。
- 已区分经验分布与医疗效果，没有承诺无风险或法律豁免。
- 明确了排名独立人数、时间窗、算法、空数据、撤回规则及当前接口缺口。
- 已分离科普与具体医院导流；未设计虚假口碑或全国全覆盖承诺。
- 待外部解决项：设计批准、地图授权配置、院区逐条核验、共享后端上线确认与正式排名法律审阅。
