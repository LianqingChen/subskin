# 分享页帖子排序与转发功能设计

> 日期：2026-08-24
> 需求：分享页（/community）帖子排序需要明确规则——默认浏览多、点赞多、转发多的帖子往前放；调研小红书排序/推荐规则并复用。

## 一、小红书规则调研结论（复用依据）

| 小红书规则 | 说明 | 复用方式 |
|-----------|------|---------|
| CES 互动评分 | `点赞×1 + 收藏×1 + 评论×4 + 转发×4 + 关注×8`，深度互动（评论/转发/收藏）权重远高于轻度互动（点赞/浏览） | 热度分公式按此思想设计 |
| 互动率优先 | 单纯浏览多但无互动不推；浏览量只是分母 | 浏览权重设得很低（0.1） |
| 时间衰减 | 热度榜通常只统计近期内容（常见 7 天窗口），防止老帖永久霸榜 | 半衰期 7 天的指数衰减 |
| 显式排序入口 | 推荐/最新/最热等排序切换 | 分享页新增排序选项行 |

参考来源：[2026 年算法解析](https://hashmeta.com/cn/posts/xiaohongshu-algorithm-2026)、[CES 评分机制](https://hashmeta.com/cn/posts/xiaohongshu-algorithm-2026-seeding-strategy)、[流量机制解析](https://matrix.newrank.cn/article/article-detail/bc749c648b4c4a23)、[算法逻辑 2025](https://www.ganhuoku.cn/archives/318310)。

## 二、现状问题

1. 后端虽有热度排序（`点赞×2 + 评论×2.5 + 浏览×1`），但**无收藏/转发权重、无时间衰减**；
2. 前端 `CommunityPage.vue` 的 `mergePosts` 在客户端按 `created_at` 重新排序，**把后端热度排序覆盖掉**，导致"推荐"Tab 实际按最新排；
3. 帖子详情页已有"分享"面板（复制链接/微信/微博/海报），但**没有转发计数**；
4. `Post` 表没有 `share_count` 字段。

## 三、方案（方案 A + 转发功能，用户已确认）

### 3.1 综合热度分（默认排序，小红书式 CES + 时间衰减）

```
heat   = 点赞×1 + 收藏×2 + 评论×3 + 转发×4 + 浏览×0.1
decay  = 0.5 ^ (距今天数 / 7)          # 半衰期 7 天
score  = heat × decay
```

- 深度互动（转发 4 / 评论 3 / 收藏 2）权重高，轻度互动（点赞 1 / 浏览 0.1）权重低，符合小红书"深度互动 > 轻度互动"；
- 浏览量参与排序（满足需求），但权重低避免刷量霸榜；
- 时间衰减保证新帖有机会露头，老帖自然下沉；
- 新帖热度为 0 时按 `created_at` 兜底（等同小红书新笔记初始流量池的冷启动）。

### 3.2 排序选项（分享页"推荐"Tab 下新增一排可横滑排序胶囊）

| 选项 | 后端 sort 参数 | 排序逻辑 |
|------|---------------|---------|
| 综合（默认） | `hot` | CES 热度分 × 时间衰减 |
| 最新 | `newest` | created_at 倒序 |
| 最多浏览 | `views` | read_count 倒序 |
| 最多点赞 | `likes` | 点赞数倒序 |
| 最多收藏 | `bookmarks` | 收藏数倒序 |
| 最多转发 | `shares` | share_count 倒序 |

排序选项只作用于"推荐"Tab（关注按时间、同城按距离不变）。

### 3.3 转发功能与计数

- `Post` 表新增 `share_count` 列（可加性迁移，alembic 003，不动老数据）；
- 新增 `POST /community/posts/{id}/share`：需登录，`share_count +1` 并写入 `UserInteractionLog(action_type='share')`（推荐算法数据源），返回最新转发数；
- 前端复用详情页已有的分享面板（`PageShareSheet`），在"复制链接/微信/微博/系统分享"成功时调用计数接口；
- 帖子瀑布流卡片（`PostCard`）新增转发按钮（图标 + 计数），打开同一分享面板；
- 详情页底部操作栏"分享"改为"转发"，显示转发数。

### 3.4 前端排序 bug 修复

`mergePosts` 不再按 `created_at` 客户端重排：首屏保持后端返回顺序，我的私密日记追加在首页末尾（个人内容不参与公共热度排序），加载更多按后端游标顺序追加。

## 四、接口变更

- `GET /community/posts` 新增可选参数 `sort`（hot/newest/views/likes/bookmarks/shares，非法值忽略）；
- `POST /community/posts/{post_id}/share` → `{ share_count: number }`（需登录，WriteRateLimit）；
- `Post` 序列化模型新增 `share_count`（默认 0，向后兼容）。

## 五、风险与合规

- 后端为共享后端：迁移与接口变更**立即影响正式环境**（已向用户提示，用户确认）；
- 迁移为加列操作，不删不改老数据，满足"additive only"；
- 转发计数需登录，未登录用户仍可复制链接（不计数），与点赞/收藏一致；
- 热度分 + 游标分页存在极端情况下重复/跳过的既有行为（沿用现状，不额外扩大影响）。
