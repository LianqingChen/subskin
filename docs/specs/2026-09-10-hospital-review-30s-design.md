# 医评 · 「30 秒写出第一条评价」一期设计

> 2026-09-10 用户确认范围：①一期 = 页面重排 + 30 秒快评 + 场景入口 + 有用投票 + 中性标签云（只读）；②正文门槛**维持 ≥20 字**；③**凭证图一期一起做**。
> 二期/三期见文末「非目标」，本文件只覆盖一期。

## 一、问题与目标

**诊断（代码事实）**
1. 写评价入口在页面第 5 屏（第二步板块内），首屏没有任何"写"的动作 → 打开即劝退。
2. 评价表单一次要求 15+ 字段（对象/医生/方案/月份/疗程/费用/4 项评分/标签/正文），手机一屏放不下 → 中位完成时间 3–5 分钟。
3. 医院卡片只显示「X 条评价 · ★4.3」→ 新病友看不出"这家医院常被提到什么"。
4. 无有用投票、无凭证、无作者反馈 → 写的人得不到回报，看的人不敢信。

**一期目标（只解决"愿意写"）**

| 指标 | 现状 | 目标 |
|---|---|---|
| 进入医评 → 打开快评 | 无埋点 | 可测（新增埋点） |
| 打开快评 → 发布成功 | — | ≥ 40% |
| 中位完成时长 | 3–5 分钟（估算） | ≤ 60 秒 |
| 有评价的医院 | 0 / 7 | ≥ 50% |

## 二、用户路径（30 秒）

```
进入医评 → 首屏看到「我刚看完病，写两句」→ 点开
  ① 选医院（已选/最近标记/想去/去过/搜索，1 次点击）
  ② 选对象（默认"医院"）
  ③ 点标签（值得说 / 需注意，多选）
  ④ 写一句话（≥20 字，引导语占位）
  ⑤ 发布 → "已发布，感谢你帮到后面的病友"
  · 其余（评分/费用/疗程/月份/凭证图/长文）折叠在「想说更多？」里，默认不展开
```

## 三、页面结构（重排后）

```
① 标题 + 一句话定位 + 三个动作按钮：[写评价] [找医院] [看避坑汇总]
② 地图（保留；点省份/城市=筛选）
③ 【新增】主 CTA 卡 HospitalQuickReviewCta —— "我刚看完病，写两句"
     · 已选医院 → 「评价 XX 医院 · 30 秒」
     · 未选医院 → 内联选择器（我的标记 / 搜索 / 去下面列表）
④ 第一步 选择或创建医院（保留）
⑤ 第二步 评价与分享：中性标签云 + 排序（最新 / 最有用）+ 标签筛选 + 评价列表
⑥ 我的评价（含有用数）
```
> [写评价] 滚动到 ③ 并聚焦；[找医院] 滚动到 ④；[看避坑汇总] 滚动到 ⑤ 标签云。
> 支持 `/hospitals?write=1`（场景入口直达）。

## 四、表单（两档内容）

**快速评价**（默认可见）：对象类型 + 标签（多选）+ 正文（≥20 字）+ 凭证图（可选）+ 发布。
**完整分享**（折叠「想说更多？」）：评分 4 维、每月自付、治疗时长、就诊月份、医生称呼/职称/科室、方案名称/要点。

- 实时完整度提示：「再补 2 项就是『完整分享』，更容易被病友看到」。
- 列表对 `detail_score ≥ 2` 的评价显示「完整分享」徽标，排序时轻微优先。
- 本机草稿自动保存（复用 `useHospitalNotebook`），失败可恢复；月份默认本月。
- 字段预填：医院=当前选中；时长/费用=上次填写值。

**标签（中性措辞，分两组）**
- 值得说：解释耐心、费用清楚、不乱加项、复诊方便、异地可接续、儿童友好、设备齐全、指引清楚
- 需注意：候诊较久、需多次往返、自费项目多、排期等待、沟通时间短、停车不便、异地成本高
- 历史标签（解释耐心/费用清楚/复诊方便/候诊较久/需多次往返/儿童就诊/异地就医）继续兼容展示。

## 五、凭证图（一期）

- 允许：**费用单 / 挂号单 / 处方 / 检查单** 截图，≤3 张，≤5MB，jpg/png/webp。
- **明确禁止病情照片**；上传前必须勾选确认：「已遮盖姓名、手机号、病历号，且不含病情照片」。
- 上传：`POST /api/hospitals/reviews/images`（登录 + 写限速）→ 复用 `utils/upload_validation.validate_image_upload`（扩展名+魔数校验），存 `data/uploads/hospital/{user_id}_{hash}{ext}`。
- 展示：评价卡内缩略图（点击看大图），随评价一起公开（未登录可见）。
- 访问控制：`/api/files/serve/hospital/*` 仅当图片属于 `status=visible` 且 `moderation_status != blocked` 的评价时公开（与社区公开帖图片同标准）；作者本人始终可访问；评价被下架/删除后图片对他人立即不可见。
- 风险：图片内的 PII 无法自动脱敏 → 强制勾选确认 + 审核可下架 + 卡片注明"图片由病友上传"。

## 六、有用投票

- 新表 `hospital_review_helpfuls`（`review_id` + `user_id` 唯一，additive 新表）。
- `POST /api/hospitals/reviews/{id}/helpful` 切换；返回 `{helpful_count, is_helpful}`。
- 列表返回 `helpful_count` / `is_helpful`（登录者视角）；支持 `sort=helpful`。
- 自己的评价不能投"有用"。

## 七、中性标签聚合（只读）

- 由现有 `tags` 字段聚合，医院级 `top_tags: [{tag, count}]`（Top 8），显示在评价板块顶部：
  `常被提到：解释耐心 12 · 费用清楚 8 · 候诊较久 5`
- 固定免责行：**「均为病友个人经历，不代表医院整体水平，也不构成医疗建议」**。
- 不做排名、不做"坑/踩坑指数"、下定性结论。

## 八、场景入口

| 场景 | 入口 |
|---|---|
| 手帐页保存记录后 | 结果区提示「刚就诊？写 30 秒评价帮病友」→ `/hospitals?write=1` |
| 医院卡片点「去过」后 | toast 引导「去过了？花 30 秒写两句」 |
| 地图点城市 / 卡片「选择并评价」 | 直达快评并预填医院 |

## 十、接口与数据变更（全部 additive）

| 变更 | 说明 |

## 十一、测试与验收

- 后端：凭证图（数量/大小/标签/确认勾选/魔数）、有用（幂等、唯一、自己不能投、计数正确、排序）、标签聚合、detail_score、文件授权（公开可见 / 下架后 403 / 作者可读）、既有 18 项回归。
- 前端：vue-tsc；浏览器实测 375/768/1280 + 暗色：首屏 CTA、30 秒路径、折叠区展开、凭证图上传与预览、有用投票、标签云筛选、场景入口 `?write=1`。
- 合规检查：无排名/无定性措辞、免责行齐全、凭证图确认勾选不可绕过、PII 文本仍自动脱敏。

## 十二、非目标（二期/三期）

- 二期：标签云可筛选（一期已含基础）、按费用/疗程筛选、「我已就诊」凭证审核标记、同院医生/方案聚合视图、追评提醒（3 个月）。
- 三期：语音口述 → AI 整理成评价、AI 问答引用病友评价、关注医院与更新提醒、举报与申诉通道。
- 不做：医院排名/避坑榜/"踩坑指数"、病情照片公开传播。
