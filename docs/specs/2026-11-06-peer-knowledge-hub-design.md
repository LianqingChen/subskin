## 0. 一句话定位

> **同行 = 病友一起把白癜风"看懂、记清、推进"的地方。**
> 每个人的一张照片、一条经验、一份报告，经过授权与审核，汇入一张**有出处的白癜风知识图谱**。它先帮病友看懂病因、照护与新药，再在授权下为医生和研究机构提供高质量输入。每一份贡献都能被看见、被感谢、被追溯到它帮助了什么。

产品主线是"**贡献 → 知识 → 研究 → 回馈**"的飞轮：

```
      病友授权贡献 ───────────────► 知识图谱 / 本体（有出处、分证据等级）
     （照片·自述·报告·经验）                      │
            ▲                                     ▼
            │                          病友看懂（病因·照护·前沿）
      看得见的回馈                                 │
   （足迹·影响力·研究致谢·积分）                    ▼
            ▲                          机构研究（受控、去标识、经伦理）
            └────────── 研究成果回流（通俗解读、致谢） ◄───┘
```

## 1. 对原始构想的完善要点（先看结论）

用户提出了四个支柱：信息汇集、知识图谱与本体、助力科研、回馈用户。方向正确。基于代码现状和全球先例，补充 8 个关键修正：

1. **"全量大数据"改为"分层数据资产"。** 价值不在"量全"，而在"授权清楚、结构化、纵向、可追溯"。原始个人数据**不进入**公共知识图谱。公共图谱只吸收三类内容：公开文献、经审核的知识、满足 k≥5 的匿名聚合统计。VRF CloudBank 和 23andMe 的经验都说明，信任是资产本身（§5、§9）。
2. **证据分级是知识图谱的灵魂。** 同一个页面上会同时出现"指南推荐""III 期试验""病友经验"，必须让用户一眼分清。"生活防护小妙招"若不分级，就会变成偏方传播渠道（§6.3）。
3. **"研究"支柱分两步走。** 先做"研究透明度"：数据去了哪里、产出了什么。然后才做"研究门户"。SubSkin 不是医疗机构，研究使用必须挂在合作机构的伦理审查下（§7）。
4. **激励拆成两本账。** 「贡献值」只增不减，代表荣誉与等级；「积分」可消耗，用于未来兑换。贡献值已经上线，积分兑换需要单独立项，并处理与 2026-09 白皮书"不做积分"表述的冲突（§8、§12）。
5. **最强的激励是"影响力回流"，而不是积分。** 例如"你的 12 张核对图参与了第 3 版白斑识别模型的训练""你回答的 3 个问题进入了一项病程研究"（§8.2）。
6. **贡献类型从"只有照片"扩展到"人人可贡献"。** 包括自述问卷、经验投稿、知识纠错、研究问题投票、文献众包审读。不发病的家属和刚确诊、还没拍照的病友也能参与（§8.1）。
7. **坚守红线。** 不做疗效排行，不做个人排行榜，不按病情严重度或照片数量定价，不推荐具体药品或产品，不用"患者名义"给任何商品背书（§9）。
8. **先补基础缺口再盖楼。** 当前新标注工作台产出的金标准**不计入采纳和积分**，部位词表有两套，标准文档里的同意用途名和代码不一致（§11）。

## 3. 目标、非目标与设计原则

### 3.1 目标

| 编号 | 目标 | 衡量 |
|---|---|---|
| G1 | 让病友 **5 分钟看懂**：为什么会得、该注意什么、有哪些新药 | 主题卡读完率、"有帮助"率、问答中同类基础问题占比下降 |
| G2 | 把用户贡献沉淀为**可追溯、可撤回、分证据等级**的知识与数据资产 | 有效贡献者数、授权覆盖率、审核通过率 |
| G3 | 在授权与伦理框架下，为机构研究提供**可信输入** | 合作机构数、经伦理批准的项目数、数据卡完整度 |
| G4 | 让贡献者**感到被看见**，并带动更多人参与 | 月度有效贡献者、二次贡献率、撤回率（护栏指标） |

### 3.2 非目标（本期明确不做）

- 不做诊断、治疗方案生成、剂量建议，不做"和你相似的人用 X 药效果最好"这类推荐
- 不做疗效、医院、医生、药品排行
- 不做个人贡献排行榜（只做集体目标）
- 不收集基因检测数据，不做生物样本库
- 不向任何第三方出售或提供可识别个人数据，不把原始照片批量交给外部机构
- 不做现金兑付（未来的物质激励限于实物、服务或公益捐赠，且需法务确认）

### 3.3 设计原则

1. **信任先于规模。** 每一条进入知识或研究的数据都能回答三个问题：谁授权的、用于什么、能否撤回。
2. **出处先于结论。** 每张知识卡、每条图谱关系都显示来源、证据等级和最后审核日期。
3. **人人可贡献。** 贡献不只是照片，也不奖励"更严重"或"更多张"。
4. **集体荣誉优先于个人比较。** 用共同里程碑代替排行榜。
5. **诚实的数字。** 只展示数据库里真实、可核验的统计（STD-01 §3.6）。数字不足时显示"积累中"，不编造。
6. **AI 有标签，人有把关。** LLM 产出一律标"AI 整理"，进入公开知识前须经人工审核，医学内容须经医学审核。

## 4. 用户与场景

| 角色 | 典型场景 | 同行页给什么 |
|---|---|---|
| 新确诊病友 | "我为什么会得？会不会扩散？能治好吗？" | 病因机制故事图、分型说明、就医准备清单、"大家最常问" |
| 长期病友 | "最近有新药吗？光疗多久见效？夏天怎么防晒？" | 前沿管线看板、证据分级的照护卡、病友经验（标注等级） |
| 家属与照护者 | "孩子得了，怎么帮他？" | 儿童与心理支持主题、可贡献"照护经验" |
| 积极贡献者 | "我的照片有用吗？帮到谁了？" | 贡献足迹、影响力回流、研究致谢、等级与徽章 |
| 医生与研究者 | "有没有中国人群的真实世界数据？" | 研究透明度页、数据卡、项目申请入口（P3 起） |
| 运营与审核 | 审核知识、处理纠错、发布研究公示 | 管理后台：知识审核队列、图谱编辑、项目登记 |

## 5. 支柱一：信息汇集（分层数据资产）

### 5.1 数据来源与入图规则

**站内数据（必须在授权闸门之后才能使用）**

| 来源模块 | 可用的结构化字段 | 授权闸门 | 进入知识层的方式 |
|---|---|---|---|
| 日记 / VASI | 部位、面积、分期、用户核对标记、拍摄日期、质量报告 | `health_data` + `model_training` / `research_project` | 仅以匿名聚合统计进入（k≥5），如"面部记录占比""核对后面积分布" |
| 自述问卷 | 病程、近期变化、治疗、确诊情况、分型、外伤、自身免疫 | `health_data`；研究用途另需 `research_project` | 匿名聚合，如"自述合并甲状腺疾病的比例"，标 T1 自报 |
| 治疗事件 / 治疗分享 | 方式、药名、时长、主观效果 1–5、费用区间、副作用 | 分享时的公开授权；研究用途另需授权 | 只进"病友经验"层，**不得**生成疗效排行，聚合须 k≥5 |
| 体检报告 | 解析出的指标与异常项 | `health_data` + `research_project` | 仅研究授权后以聚合形式进入（如"自报合并甲功异常"），不进公共知识卡 |
| 分享帖 | 标签、类型、AI 抽取字段 | 公开发布即公开；仍须内容审核 | 可作为"病友经验"候选，经编辑改写、去标识后入库，并征得原作者同意署名 |
| 就医经验 | 就诊月份、治疗名、费用区间、自报结局 | `health_consent` | 只用于就医信息，不做医院或疗效比较 |
| 问答 | 自由文本 | `ai_data` | **不抽取内容入图**。只做去标识的"高频问题主题统计"，用来发现知识缺口（需在隐私政策中写明此用途，见 §9.4） |

**站外数据（公开来源）**

| 来源 | 用途 | 展示规则 |
|---|---|---|
| PubMed / OpenAlex / Europe PMC（已有爬虫） | 论文、综述、机制研究 | 题录 + "AI 整理的中文要点" + 原文链接，不大段转载摘要 |
| ClinicalTrials.gov / ChiCTR / WHO ICTRP | 临床试验 | 试验名、阶段、地区、状态、终点，链接回注册页 |
| NMPA / CDE / FDA / EMA 公告 | 审批里程碑 | 只写事实与日期，附原文链接 |
| 药企新闻稿 / 基金会新闻（已有 `foundation_news`） | 研发动态 | 标明"企业发布"，不转述疗效宣传语 |
| 指南与共识（如《白癜风诊疗共识（2024 版）》） | "指南推荐"层的权威来源 | 引用条目与年份，不复制全文 |
| 开放本体（MONDO、HPO、MeSH、ChEBI/ChEMBL、Open Targets） | 实体主键与关联 | 遵守 CC BY / CC0 署名要求 |

### 5.2 三层资产模型

```
┌────────────────────────────────────────────────────────────────────┐
│ L-公开知识层（Public Knowledge）                                    │
│ 文献·试验·指南·审核后的知识卡·k≥5 的匿名聚合统计                       │
│ → 所有人可见；图谱节点与关系都带出处和证据等级                          │
├────────────────────────────────────────────────────────────────────┤
│ L-社区聚合层（Community Aggregate）                                 │
│ 去标识的统计视图（部位分布、病程分布、自述共病比例……）                  │
│ → 同行页大盘、研究透明度页；最小单元格 ≥5，否则隐藏                    │
├────────────────────────────────────────────────────────────────────┤
│ L-授权研究层（Consented Research）                                  │
│ 个体级去标识数据 + 金标准图像，仅限持有效 research_project 授权的记录   │
│ → 只在受控环境中供经伦理批准的项目使用；撤回后进入清理流程               │
└────────────────────────────────────────────────────────────────────┘
          ▲ 原始个人数据（L3）始终留在用户自己的空间，默认不进入任何上层
```

### 5.3 汇集管线

在已有爬虫和调度器上扩展，不重造：

```
采集（crawlers，按周/日）
  → 去重与许可判定（deduplicator + 许可证字段）
  → 实体识别与对齐（PubTator3 / LLM 本体约束抽取 → MONDO/ChEBI/HGNC ID）
  → 结构化声明抽取（claim：主语-关系-宾语 + 原文句 + PMID）
  → 自动质检（引用必须能回溯原文句；与已有声明冲突时标红）
  → 编辑审核（运营）→ 医学审核（合作医生，A/B 级证据必审）
  → 版本化发布（图谱 + 知识卡 + RAG 重新索引）
  → 定期复审（默认 12 个月；新药状态 3 个月）
```

## 6. 支柱二：知识图谱与本体

### 6.1 白癜风本体 v0（工作名 VitiOnto）

**核心类（实体）**

| 类 | 示例 | 外部对齐 |
|---|---|---|
| 疾病与亚型 `Disease` | 白癜风（`MONDO:0008661` ✅）、非节段型、节段型、混合型、泛发型（`MONDO:1010125` ✅）、三色白癜风（`MONDO:1010122` ✅） | MONDO / MeSH / DOID |
| 机制 `Mechanism` | 氧化应激、黑素细胞脱落、IFN-γ–CXCL9/10–CXCR3 轴、JAK-STAT 通路、组织驻留记忆 T 细胞 | GO / Reactome（待定） |
| 基因与靶点 `Gene/Target` | JAK1/2/3、TYK2、IFNG、CXCL10 等 | HGNC / UniProt / Open Targets |
| 诱因与风险因素 `Trigger` | 皮肤外伤（同形反应 / Koebner）、晒伤、精神压力、某些化学物（如酚类） | HPO / 自定义 |
| 合并症 `Comorbidity` | 自身免疫性甲状腺疾病、斑秃等 | MONDO |
| 表现与体征 `Sign` | 白斑、毛发变白、Wood 灯表现、纸屑样色素脱失、三色现象 | HPO |
| 评估量表 `OutcomeMeasure` | VASI、F-VASI、T-VASI、VES、VNS、VitiQoL | 自定义 |
| 治疗 `Intervention` | 外用激素、钙调磷酸酶抑制剂、外用/口服 JAK 抑制剂、NB-UVB、308nm 准分子、手术移植、遮盖 | ChEBI / ChEMBL / 自定义 |
| 药物 `Drug` | 芦可替尼乳膏、乌帕替尼、利特昔替尼、povorcitinib…… | ChEMBL / DrugBank 开放字段 |
| 临床试验 `Trial` | Viti-Up-1/2、TRANQUILLO、STOP-V1/2、NCT07865312 | NCT / ChiCTR 号 |
| 监管事件 `RegulatoryEvent` | 批准、突破性治疗认定、申报 | 自定义（地区 + 机构 + 日期） |
| 照护建议 `CareAdvice` | 防晒、避免摩擦与外伤、心理支持、遮盖化妆 | 自定义 |
| 部位 `BodySite` | 与 `web/shared/body-sites.json` **统一** | 自定义 |
| 证据 `Evidence` | 论文、指南条目、试验结果、社区聚合观察 | PMID / DOI / NCT |
| 社区观察 `CommunityObservation` | "自述合并甲状腺疾病的比例为 X%（n=…，T1 自报）" | 自定义，**永远标注自报与样本量** |

**核心关系（谓词，节选）**

`has_subtype`、`involves_mechanism`、`associated_gene`、`triggered_by`、`comorbid_with`、`presents_as`、`treated_by`、`targets`（药物→靶点）、`studied_in`（药物→试验）、`trial_reports_outcome`、`has_regulatory_event`、`care_advice_for`、`measured_by`、`supported_by`（任意声明→证据）。

**每条关系必须带的元数据**

| 字段 | 说明 |
|---|---|
| `evidence_level` | A 指南/系统综述 · B RCT/III 期 · C 观察性研究/小样本 · D 专家意见/病例 · **E 病友经验（未经验证）** |
| `sources[]` | PMID / DOI / NCT / 指南条目 / 聚合查询 ID |
| `quote` | 支撑该关系的原文句（用于回溯） |
| `extracted_by` | `llm:<model>@<prompt_version>` 或 `human:<editor_id>` |
| `status` | draft → reviewed → medical_reviewed → published → retired |
| `confidence` | 抽取置信度（仅内部使用，不对用户展示成"可信度百分比"） |
| `region` | 适用地区（如药物仅欧盟获批） |
| `reviewed_at` / `next_review_at` | 复审周期 |

### 6.2 构建方法

1. **人工骨架（约 150–300 个核心节点）。** 由编辑与合作医生维护病因、分型、主流治疗、照护建议的主干，加一张中文别名表（白癜风 / 白驳风 / 白斑……→ `MONDO:0008661`）。
2. **LLM 本体约束抽取（借鉴 OntoGPT/SPIRES 思路）。** 用 Qwen 按本体模式从文献题录和开放全文中抽取声明，输出必须带 ID 和原文句。没有原文句的声明丢弃。
3. **PubTator3 辅助。** 用于药物、基因的实体标注，作为 LLM 抽取的交叉校验。
4. **冲突检测。** 新声明与已发布声明矛盾时（如不同试验结论不同），不覆盖，并列展示并标注。
5. **人审闸门。** A/B 级关系与所有"治疗""药物"相关关系必须医学审核后才能发布。
6. **检索增强层。** RAG 检索时把图谱邻域（实体 + 一跳关系 + 证据）拼进上下文，让问答引用同一份事实。规模扩大后可评估 LightRAG（MIT，支持 Qwen 和 PostgreSQL，已核验）或 KAG（中文友好但部署重）。

### 6.3 用户可见的知识产品

| 产品 | 形态 | 内容规则 |
|---|---|---|
| **病因机制图**"为什么会得白癜风" | 5–7 步的通俗故事图（诱因 → 免疫攻击 → 黑素细胞受损），每一步可展开看证据 | 只呈现共识与 A/B 级证据；有争议的标"研究中" |
| **主题知识卡** | 分型、会不会扩散、日常注意、防晒、饮食误区、心理、儿童、就医准备 | 每张卡显示证据等级徽标、来源数量、最后审核日期、"AI 整理 · 医学审核"标签 |
| **生活防护小妙招** | 病友投稿 + 编辑整理 | 分两栏："指南建议"（A–C 级）和"病友经验"（E 级，显式标注"个人经验，未经研究验证，不替代医嘱"）；涉及药品、偏方、产品购买的投稿一律不收 |

| **论文速递** | 每周 3–5 篇，"一句话看懂 + 为什么值得关注 + 局限" | 标注研究类型与样本量；预印本标"未经同行评议" |
| **知识图谱探索**（桌面端为主） | 可视化子图：点击"乌帕替尼"→ 靶点 / 试验 / 监管事件 / 证据 | 默认只显示 published 关系；移动端降级为列表 |
| **问答联动** | 问答回答底部"在同行查看完整证据"；知识卡底部"还有疑问？问问小白" | 同一份事实，双向跳转 |

## 7. 支柱三：助力科研

### 7.1 分三步走

| 阶段 | 做什么 | 不做什么 |
|---|---|---|
| **R1 研究透明度**（先做） | 公开数据用途清单：哪些授权、用于哪些项目、产出什么（模型版本、论文、报告）；每个项目有公示卡 | 不对外提供任何个体数据 |
| **R2 研究共创** | 病友提出研究问题、投票（学法国 ComPaRe）；研究者认领；结果通俗回流 | 不承诺研究一定开展 |
| **R3 受控研究合作** | 与合作机构签数据使用协议（DUA），项目经其伦理委员会批准；数据**不出平台**，在境内受控环境中分析，只导出聚合结果；必要时联邦学习（学 Owkin） | 不批量交付原始照片；不做数据出境 |

### 7.2 研究项目全流程（复用 `research_project` 授权用途）

```
机构提交项目申请（目的、数据字段、伦理批件、期限、联系人）
  → SubSkin 内部评审（最小必要、隐私影响评估）
  → 项目公示卡上线（同行 · 科研栏目）
  → 用户逐项目单独授权（research_project + project_id，默认不勾选）
  → 受控环境分析（审计日志，k≥5 输出闸门）
  → 结果回流：通俗摘要 + 论文链接 + 致谢（参与人数，用户可选署名）
  → 项目到期 / 用户撤回 → 清理任务（DataRightsJob）
```

### 7.3 面向机构的交付物

- **数据卡（Data Card）。** 借鉴 SCIN 与 Datasheets for Datasets：采集方式、同意文本版本、样本量、部位 × 肤色 × 设备覆盖矩阵、标签等级（T1 自报 → T2 标注员 → T3 医生 → T4 仲裁）、已知偏差、撤回机制。
- **标准导出层（P4 之后）。** 研究导出映射到 OMOP CDM 或 FHIR，内部存储不改。
- **研究者工具。** 已在战略文档 08 规划的医生扫码确认（≤90 秒）、盲审队列、医生贡献看板，这些也是"医生参考 +20"规则启用的前提。

### 7.4 合作对象优先级（建议）

1. 一家三甲医院皮肤科：伦理背书与医学审核，最关键。
2. 国内白癜风研究团队（如中国白癜风精准医学研究联盟的牵头单位）。
3. 国际非营利组织（VRF / GVF）：知识共享与 World Vitiligo Day（6 月 25 日）联合活动。
4. 药企：仅限患者教育与经伦理批准的真实世界研究，须公开披露合作，不得以数据换取广告。

### 8.2 精神激励（P1 起）

| 机制 | 说明 |
|---|---|
| **影响力回流** ⭐ | "你的贡献帮助了什么"时间线：图片参与了哪一版模型训练、问卷进入了哪个研究项目、纠错被多少人读到。只陈述可验证事实，不夸大因果 |

### 8.3 物质激励（P3 试点，需单独立项）

**两本账设计**

| | 贡献值（已有） | 积分（新增） |
|---|---|---|
| 性质 | 荣誉，只增不减 | 可消耗 |
| 决定 | 等级、徽章 | 兑换资格 |
| 来源 | 所有贡献 | 与贡献值同步获得（1:1），但设年度封顶 |
| 撤回授权后 | 保留 | 已兑换不追回，未兑换保留 |

**兑换设计（参照 Evidation：10,000 分 = 10 美元，可兑礼品卡或捐赠，日获取上限约 40 分）**

- **兑换物。** 实物和服务优先，不提供现金：防晒用品、遮盖化妆体验、线下病友活动名额、科普书籍、心理支持课程。**公益捐赠作为默认选项之一**，例如"捐给白癜风公益项目"。研究表明，允许捐赠可以缓解金钱激励的挤出效应。
- **年度封顶。** 单用户年度兑换价值上限建议 200–300 元（待法务和伦理确认），确保是"致谢"而不是"收入"。
- **禁止。** 积分不可转让、不可提现、不可购买；不得兑换药品、处方或医疗服务；兑换品不得出现药品或疗效宣传。
- **反作弊。** 新账号 30 天冷却；同设备、同哈希去重（已有 `image_hash` 去重）；异常增长人工复核。
- **合规前置。** 伦理意见（"补偿"而非"利诱"，见伦理审查办法）；《反不正当竞争法》有奖销售规则（如做抽奖）；个税与发票处理；兑换规则公示与变更通知。

## 9. 合规、伦理与信任设计

### 9.1 红线清单

| 红线 | 依据 | 落地 |
|---|---|---|
| 健康数据须单独同意 | PIPL 第 28、29 条 | 已有 `health_data` 同意；研究用途逐项目授权，默认不勾选 |

| 不利诱参与 | 同上 | 积分按"致谢/补偿"设计，封顶、可捐赠 |
| 不做功效断言、不以患者名义背书 | 《广告法》第 16 条；《药品、医疗器械……广告审查管理暂行办法》第 11 条 | 前沿看板只写事实；病友经验不出现品牌和购买渠道；不做疗效排行 |
| 不做诊疗 | 互联网诊疗相关规定（待法务细化） | 知识卡定位为健康科普，带"本文不构成医疗建议"（AGENTS.md） |
| AI 内容标识 | 《人工智能生成合成内容标识办法》 | 沿用站点"AI 整理"标签 |
| 不碰基因数据 | 《人类遗传资源管理条例》实施细则 | 第一阶段不收基因检测报告 |
| 数据不出境 | 数据出境相关规定 | 境外合作只输出聚合结果 |
| 不做排名 | STD-01 | 无疗效、医生、个人贡献排行 |

### 9.2 同意书必须补充的条款（23andMe 教训）

- 公司被并购、破产或控制权变更时数据如何处置，用户保留删除权和研究退出权
- 研究用途发生变化时重新取得同意（不使用"可退出"代替"选择加入"）
- 每个研究项目的数据保存期限和到期清理

### 9.3 透明度机制

- **数据去向页**（同行 · 科研栏目）：列出所有正在使用社区数据的用途和项目
- **年度透明度报告**：授权数、撤回数、清理完成率、项目数、产出
- **一键查看"我的数据在哪里"**：扩展现有 `/profile/data` 页

### 9.4 需要同步修订的文档

- 隐私政策：新增"问答主题去标识统计"用途、研究项目授权说明、控制权变更条款

- 2026-09 白皮书："不做积分"表述需更新，说明积分只作致谢且不奖励病情和数量（§12 待决策）

## 15. 风险与对策

| 风险 | 对策 |
|---|---|
| LLM 抽取出错导致错误医学知识 | 必须附原文句；A/B 级与药物相关关系全部人审；冲突并列展示；用户可一键纠错 |
| "病友经验"变成偏方或广告渠道 | E 级强标注；药品、偏方、品牌、购买渠道一律不收；关键词与 `content_safety` 双重过滤 |
| 积分引发刷量或"为积分上传病情" | 不按数量和严重度计分；周期封顶；审核后发放；异常复核 |
| 研究合作引发信任危机 | 逐项目授权、公示、透明度报告、控制权变更条款；不出售数据 |
| 数字太小、看起来"冷清" | 先用集体里程碑和知识内容撑起页面；k≥5 隐藏规则不放松；不造数 |
| 医学审核人力不足 | P1 只发少量高质量卡；前沿看板只写事实，降低审核负担 |
| 前沿信息过时 | `next_review_at` 到期提醒；新药状态 3 个月复审；页面显示"最后核对日期" |
