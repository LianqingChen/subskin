# 医评 · 统一设计与改版（v3）

> 日期：2026-09-11 ｜ 依据：`docs/specs/2026-09-11-medical-review-research.md`（好大夫在线 / 名医汇 / 复旦榜 / 国家卫健委国考 / 北京市卫健委绩效考核 + 法规原文 + 名誉权判例）
> 前置版本：`2026-09-10-hospital-review-30s-design.md`（一期 30 秒快评）、`2026-09-10-hospital-map/design-v2-review-sharing.md`（二版公开评价）
> 用户已确认的三个抉择：①**去掉医院级平均分**，改「维度提及分布」；②风控采用**先发后审 + 聚合冷处理**；③**全做**（发布前预警 + 发布后评分 + 举报 + 申诉 + admin 看板）

## 一、定位（一句话）

**医评 = 病友的个人就医体验记录，不是医院/医生的评比或排行平台。**

由此推导出三条不可逾越的红线（写进代码常量与审核规则，不靠人记）：

| 红线 | 依据 | 产品约束 |
|---|---|---|
| 不做疗效评价与比较 | 《广告法》16 条；《医疗广告管理办法》7 条 | 不设疗效/治愈率/有效率/医术/诊断准确率维度与字段；不做任何比例、排名、榜单 |
| 不用患者评价做机构推广 | 《医疗广告管理办法》2 条（含**间接**介绍）+ 7 条(六)（利用患者名义形象作证明） | 评价区**不得**出现挂号/导诊/购买转化按钮；**不得**做「好评精选/名医推荐/医院导流位」；不得与医院名称+地址+联系方式同页组合用于推销 |
| 不泄露个人健康信息 | 《基本医疗卫生与健康促进法》92 条；《个人信息保护法》28/29/30 条 | 病情描述属敏感个人信息 → **单独同意**（禁默认勾选）；凭证图默认**不公开**；作者可逐条删除 |

## 二、统一评价体系（本次核心）

### 2.1 两层结构：对象 × 体验维度

**对象（target，保留现有 4 类）**：医院 / 医生 / 治疗方案 / 治疗经历。

**体验维度（统一 6 维，所有对象共用）** —— 维度名取自国家卫健委满意度调查的维度名（挂号体验 / 医患沟通 / 医务人员回应性 / 隐私保护 / 环境与标识）+ 现有 4 维合并，**不含任何疗效维度**：

| 维度 | 引导题干（白话，降低认知负担） |
|---|---|
| 挂号与预约 | 号好不好挂？你是怎么挂到的？ |
| 候诊与流程 | 等了多久？指引和动线清楚吗？ |
| 医患沟通 | 医生有没有把方案和注意事项讲清楚？你的疑问得到回应了吗？ |
| 费用与告知 | 哪些是自费的？事先说明了吗？ |
| 复诊与连续性 | 复诊好约吗？需要异地来回跑吗？ |
| 环境与隐私 | 候诊环境、隐私保护、儿童/无障碍是否友好？ |

**每题 4 档（非对称 + 不适用档）**：`满意 / 一般 / 不满意 / 没体验过`

- 采用**非对称档位 + 「不适用」档**，与国考满意度问卷（公开转载版）的"非对称 4 级 + 不知道/没接触过"结构同构；**不设"非常满意/非常不满意"**，减少情绪极化与刷分动机。
- 「没体验过」档是**诚实度开关**：强迫表态会制造噪音，且该档天然抑制刷分（参考名医汇"暂未评价"档）。

**禁止维度黑名单**（代码常量 + 后端校验 + 审核兜底）：
`疗效 / 治愈 / 有效率 / 好转率 / 医术 / 诊断准确 / 死亡率 / 复发率 / 并发症 / 根治 / 排名 / 最好 / 第一`

### 2.2 效果自述（保留但降级、与评分严格分离）

保留现有 `outcome` 字段，措辞改为**第一人称过程性描述**（对齐好大夫「有好转」式规避范式）：
`仍在观察 / 我治疗后白斑有变化 / 我没有感觉到变化 / 我已停止治疗`
固定后缀声明：**「这是我自己的感受，个体差异很大，不代表疗效，也不代表医生的诊疗水平。」**

> 研究明确：好大夫采「疗效满意度」但改称**患者主观疗效**、标签用过程性描述——这是可复用的规避范式。但 SubSkin 面对的是病友社区而非挂号转化场景，**更稳妥的做法是不聚合、不排序、不进任何比例**。

### 2.3 聚合展示改造（用户已选：去掉平均分）

| 位置 | 现在 | 改为 |
|---|---|---|
| 医院卡片 / 列表 | `★4.3 分` | `N 条病友评价 · 常被提到：解释耐心 等`（**无任何分数**） |
| 医院对比表 | 「主观评分」行 | **删除该行**，只比客观字段（城市/类型/科室/诊疗服务/评价条数） |
| 评价板块顶部 | `暂无评分 / 4.3 分` 徽标 | **维度提及分布条**（见下） |
| 排序 | 最新 / 最有用 | 不变（**不新增"评分最高"**） |

**维度提及分布条**（替代平均分）：

```
病友怎么说 · 共 42 条评价
挂号与预约   ██████████  满意 28 · 一般 6 · 不满意 3 · 没体验过 5
医患沟通     ████████    满意 31 · 一般 4 · 不满意 2 · 没体验过 5
费用与告知   ██████      满意 18 · 一般 7 · 不满意 9 · 没体验过 8
```

- 计数型、含"没体验过"档 → 天然抑制刷分，且**没有任何可被截图当作"医院得分"的数字**。
- 医院级**不提供**跨院排序、榜单、推荐位；`rating_avg` 字段保留（不删列、不破坏历史），但**不再用于任何 UI 展示与排序**。
- 板块固定免责条：**「评价来自病友个人经历，不代表医疗水平评价，仅供参考」「仅作病友自身经历记录，不在医院之间比较」**（自拟，**不伪称引自官方**——研究确认国考官方文件并无中立免责措辞）。

## 三、页面结构（统一改版）

```
医评 /hospitals
├─ 页头：定位一句话 + [写评价] [找医院] [社区公约]
├─ 页级常驻免责条（红线三条的通俗版）
├─ 地图（保留置顶）
├─ 主 CTA：我刚看完病，写两句（30 秒路径）
├─ 第一步 选择/创建医院（卡片去掉星级 → 评价数 + 常被提到标签）
├─ 第二步 评价与分享
│   ├─ 维度提及分布条（新，替代平均分）
│   ├─ 常被提到标签云（保留，可筛选）
│   ├─ 排序：最新 / 最有用
│   ├─ 评价列表
│   │   卡片：脱敏作者 · 就诊月份 · 时间衰减标（>18 个月：「时间较早，仅供参考」）
│   │         · 凭证徽标（仅徽标，不公开原图）· 完整分享徽标
│   │         · 有用 · 举报 · 我的可删 / 可申请复核
│   └─ 写评价入口
├─ 我的评价（含被限流/被驳回答疑入口）
└─ 页脚：三层免责 + 本机记录说明 + [评价申诉入口]
```

新增独立页：
- `/hospitals/rules` **社区公约**（《生态治理规定》15 条要求公开管理规则与平台公约）——目前 SubSkin **缺失**，属硬性缺口。
- `/hospitals/appeal` **申诉**（被评价方 / 被误判作者共用入口）。

## 四、引导用户填写（提高质量而非数量）

三档渐进，尊重"愿意写才有数据"：

1. **30 秒点选**：选对象 → 点 3 个维度的满意/一般/不满意 → 选标签 → 发布（正文门槛保留 ≥20 字，但先给结构化点选降低起步成本）。
2. **1 分钟写一句**：编辑器顶部**五要素提示条**「时间 · 地点 · 流程 · 费用 · 沟通」，命中 ≥3 个要素给「内容具体」正反馈（**提示不阻断**）。
3. **完整分享**（折叠"想说更多？"）：费用区间 / 疗程 / 就诊月份 / 医生脱敏称谓 / 方案 / 凭证图。`detailScore ≥2` 显示「完整分享」徽标（**徽标，不加权、不排序**）。

配套：
- **本机草稿自动保存**（已有 `useHospitalNotebook`）。
- **场景化触发**（已有）：标记「去过」、手帐保存记录、`?write=1`。
- **凭证徽标**：`已上传挂号单 / 费用单` —— **只做可信度标识，不参与任何加权或排序**（规避《医疗广告管理办法》7 条(六)）。
- **好评与差评同一套词库审核**（研究实测：好大夫被拒评价中 85% 是好评）——当前 `EXAGGERATED_WORDS` 已扫正文，本次扩展到"推荐去/治好/去吧"等正向推广措辞。

## 五、风控与预警（用户已选：先发后审 + 聚合冷处理 + 全流程）

### 5.1 发布前预警（前端，即时，帮用户把话说到站得住）

新增 `web/app/src/utils/reviewRiskRules.ts`（纯函数，可单测）：

| 规则组 | 命中示例 | 输出 |
|---|---|---|
| 情绪强度 | 骗子 / 黑心 / 谋财害命 / 没医德 / 垃圾 | `warn` |
| 断言性指控 | 就是误诊 / 肯定是医疗事故 / 害我… | `block`（给改写入口） |
| 指名指控 | 具体人名 + 贬损词同现 | `warn` |
| 组织化 / 引流 | 大家一起 / 维权群 / 曝光他 / 联系方式 | `block` |
| 疗效夸大 | 根治 / 治愈 / 100% / 包好（双向：好评差评同一词库） | `block`（给改写建议） |
| 敏感个人信息 | 手机号/身份证/银行卡（复用 `detectPii`） | `warn` + 自动脱敏说明 |
| 疑似他人病历 | 病历号 / 住院号 / 检验单号 | `warn` |

三档处置：
- **info**：提示条 + 改写建议（`"XX 就是骗子"` → `"我这次的费用构成没有提前告知"`）。
- **warn**：进入**发布前冷静确认页**——必须勾选「我已确认内容基于我的真实经历，不含侮辱性言辞，且知道它会公开」才能提交；同时给出**正当维权渠道指引**（医院医患办 / 医疗纠纷人民调解委员会 / 12345），引导而非封口。
- **block**：硬拦截并给改写入口（疗效断言、联系方式、侮辱性言辞）。

> 研究提示：**不要把"延迟发布"当行业惯例**（未能确认任何平台这么做）。因此本次冷处理只作用于**聚合**，发布立即可见（见 5.2）。

### 5.2 发布后服务端风险评分与分档处置

规则分（可解释权重）+ LLM 复核（复用 `moderate_text`）：

| 分档 | `moderation_status` | 公开可见 | 进入聚合 |
|---|---|---|---|
| 0–29 安全 | `approved` | ✅ | 立即 |
| 30–59 观察 | `flagged`（显示「待复核」小标） | ✅ | 冷处理后 |
| 60–79 受限 | `restricted`（排序垫底） | ✅ | ❌ 不聚合 |
| 80–100 高危 | `blocked` | ❌ 仅本人可见 + 明示「含违规内容，可修改后重新提交」 | ❌ |

- **聚合冷处理 30 分钟**：新评价 `aggregate_after = now + 30min`，期间不计入标签聚合 / 维度分布 / 统计。作用有二：给人工审核窗口、抑制瞬时组织化刷评。**发布本身不做延迟**。
- **异常预警**：同一医院 1 小时内 ≥N 条评价、同一账号短时间跨院评价、新注册账号集中评价 → 进预警队列，该类评价自动延长冷处理。
- **双向约束**（好大夫范式）：违规作者走「警告 → 禁言 → 限制评价」；不存在"只处罚一方"。

### 5.3 举报（用户侧）

- 新表 `hospital_review_reports`：`review_id / reporter_id / reason_code（虚假信息·人身攻击·泄露隐私·广告引流·疗效夸大·其他）/ detail / status / created_at`
- 同一用户对同一评价只能举报一次（唯一约束）；举报达阈值（≥3 个不同用户）→ 自动转 `restricted` 并入 admin 队列。
- 入口在评价卡片（《生态治理规定》16 条"显著位置便捷举报入口"）。

### 5.4 申诉（被评价方 + 被误判作者，双向）

- 新表 `hospital_review_appeals`：`review_id / claimant_type（hospital·doctor·author·other）/ claimant_name / contact / reason / evidence_urls / status（pending·accepted·rejected）/ resolution / handled_by / handled_at / due_at`
- **3 个工作日时限**（对齐美团同类规则），写入 UI 与后台待办；超时 admin 看板标红。
- 处置动作：保留 / 要求作者补充 / 隐藏（→ `blocked`）/ 追加"作者更正"。
- 入口：`/hospitals/appeal`（公开可达，无需登录即可提交，避免把机构挡在门外）+ 评价卡片「我认为这条评价有问题」。
- 全部动作写 `AuditLog`（不可篡改）——满足"发现—停止传输—保存记录—报告"闭环（《互联网信息服务管理办法》16 条）。

### 5.5 Admin 预警看板

新增 admin 页「医评风控」（`web/admin/`）：待处理举报、待处理申诉（含超时标红）、高冲突评价列表（按 `risk_score`）、异常集中度预警、处置动作（保留/隐藏/更正）。复用现有 admin 导航与鉴权。

### 5.6 用户救济

作者可删除（已有）、可对被误判的评价提交申诉（同一申诉表 `claimant_type=author`）、可在卡片看到限流/驳回原因与改写入口。

## 六、合规护栏清单（逐条对照研究表 E）

| # | 措施 | 依据 |
|---|---|---|
| 1 | 无疗效/治愈率字段与聚合，黑名单硬校验 | 广告法 16；医疗广告管理办法 7 |
| 2 | 无排名/榜单/推荐位；评价区无挂号导流按钮 | 医疗广告管理办法 2 + 7(六)；广告法 16 |
| 3 | 医生默认**脱敏称谓**「张医生（皮肤科）」，不落真名/联系方式/工号（**修复现有缺口**） | 基本医疗卫生与健康促进法 57；名誉权判例 |
| 4 | 病情描述类评价首次发布需**单独同意**（不默认勾选）+ 写入审计 | PIPL 28/29/30/25 |
| 5 | 三层免责声明（页级/板块级/单条），**自拟不伪称官方** | 名誉权抗辩；平台中立 |
| 6 | 社区公约页 + 一键举报 + 3 工作日申诉（**修复缺失**） | 生态治理规定 15/16；民法典 1028 |
| 7 | 审核 SOP 对齐《民法典》1026 条 6 因素（来源可信度/必要性/核实成本） | 民法典 1026 |
| 8 | 凭证图**默认不公开**（仅作者与管理员可看），公开层只显示「已上传挂号单」徽标 | PIPL；医疗广告管理办法 7(六) |
| 9 | 明确禁止病历/检验单原图进入公开评价 | 医疗纠纷预防和处理条例 15/42；PIPL |
| 10 | 评价区**不得**演化为线上问诊入口；AI 只做审读/改写，不提供诊疗结论 | 互联网诊疗管理办法 2/16；监管细则 13/21 |
| 11 | 时间衰减标注（>18 个月） | 白癜风疗程长，旧评价最易失真 |
| 12 | 上线前完成 PIA（个人信息保护影响评估），报告留存 ≥3 年 | PIPL 55/56 |

## 八、非目标（明确不做，避免范围蔓延）

- ❌ 医院/医生榜单、评分排序、推荐位、导流位、广告位
- ❌ 疗效/治愈率/有效率任何形式的采集、聚合、展示
- ❌ 诚信分体系、追评提醒、院区精确导航、医生个人主页（后续可评估）
- ❌ 付费删差评 / 付费置顶好评（《生态治理规定》22 条明文禁止）
- ❌ AI 给出诊疗结论（研究确认属禁止项）

### 与设计的两处偏差（已按更稳妥方案落地）

1. **`safe` 档不做聚合冷处理**。设计初稿写「所有新评价冷处理 30 分钟」，实现时改为只对 `watch` 及以上生效 —— 否则每条正常评价都要等 30 分钟才出现在标签云里，对正常用户是无谓成本。反刷评改用「同一用户 1 小时内对同一医院 ≥3 条自动延长至 60 分钟」的异常集中度检查。
2. **`contact_info` 权重降到 20**（低于 watch 阈值 30）。手机号/邮箱会被自动脱敏，属于「可自动修复」而非需要人工复核的风险，不应把正常评价推进冷静确认。
