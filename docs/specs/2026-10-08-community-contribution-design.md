# 「同筑」Tab 页面设计 v1

日期：2026-10-08。状态：用户已于2026-10-08批准实施；Tab名称调整为「同筑」。

依据：`docs/research/2026-10-06-strategy/06-image-database-label-plan.md`，并只读核对当前导航、路由、授权页、图片标签与自报事实模型。未读取真实用户或病例数据，本文不含实际业务统计。

## 1. 已确定的范围

- 按用户最新要求，保留调养页面、商品详情、现有功能及本机购物清单，不改写调养页面。
- 实施时只隐藏调养的主导航入口；原 `/care` 和 `/care/:id` 路由保留，不重定向到新页。
- 新增独立主导航 Tab，命名「同筑」，路径 `/contribution`，图标 `ri-hand-heart-line`。
- 主导航变为：问答 · 记录 · 发现 · 同筑。桌面侧栏、平板顶栏与手机底栏使用同一配置。
- 现有 `/profile/data`「数据与贡献」页继续负责授权管理。共建页提供「管理我的数据授权」入口，避免再建一套授权逻辑。
- 设计已获批准，实施另见hermes_plan/2026-10-08-tongzhu-task_plan.md。

## 2. 产品定位与方案选择

用户应当能回答三件事：我贡献了什么；这些认真投入如何被记录和认可；我们合在一起建成了什么、还缺什么。

比较过三种组织方式：

| 方式 | 优点 | 局限 |
|---|---|---|
| 个人贡献中心 | 个人成果直观 | 社区合力不够明显 |
| 全站数据大屏 | 规模与分布突出 | 用户容易觉得与自己无关 |
| 个人贡献 + 成长等级 + 共建成果的连续页面 | 能把个人行动与整体价值连起来 | 需要明确多种数据口径 |

推荐第三种。共建是主 Tab；页内使用「我的贡献 / 贡献等级 / 共建成果」三个锚点，浏览时仍是一张连续页面，减少切页。

```text
│ 已覆盖多少 · 哪些仍待补充            │
└─────────────────────────────────────┘

下一份贡献，可以补上这里
针对真实缺口的行动建议 · 拍照指南

问答          记录          发现          共建
```

- 首屏突出个人成果和「每一份记录，汇成更多病友的参考」，不使用后台式密集数字墙。
- 沿用现有主题色、白色卡片、圆角、RemixIcon；完整支持深色模式。
- 手机：个人指标两列；影响指标单独一行；矩阵局部横向滚动，并提供易读列表切换，不让整页横向溢出。
- 桌面：个人贡献与成长卡并排；共建成果和矩阵铺满内容区。
- 统计卡点击后展示口径、当前有效量、历史贡献量、待处理量及对应本人明细。公共统计只展开匿名聚合。
- 未登录时仍可看公共成果，个人区展示「登录查看你的贡献」，不展示虚构积分。
- 动效只用于进度与采纳反馈，尊重减少动态效果的系统偏好。未产生真实里程碑前不展示庆祝动画。

## 4. 我的贡献：五项核心指标

| 指标 | 展示与计数口径 | 明细与行动 |
|---|---|---|
| 有效图片 | 本人提交、经授权校验与质量复核、去重后当前可用于已声明共建用途的图片数；旁注累计上传与待复核量 | 查看图片状态；去「记录」拍照 |
| 完成核对 | 本人实际确认的图片标注任务数；每图每个协议任务只计一次，重复编辑不累加 | 查看本人已核对任务；补充部位或范围信息 |
| 体检资料 | 独立体检报告份数，不按报告页数计；区分「已上传」和「已授权共建」 | 去体检解读；尚无对应共建授权支持时明确「共建授权待开放」 |
| 医生确认 | 本人贡献的资料中，具有已认证医生、明确依据、确认时间、版本的临床参考记录数 | 看确认状态与依据；本人提供的凭证另列「待医生核验」 |
| 预计帮助 | 有可靠发布与使用统计后，显示本人参与的数据版本未来30天预计服务的去重用户数；标明估算区间和方法 | 点开影响说明；无依据时显示「影响正在积累」，不用图片数乘固定人数 |

补充原则：

1. 普通用户的「医生确认」是其资料获得的医生参考，不表示该用户执行了临床判断。医生本人如有贡献，额外显示「我完成的医生审核」。
2. 用户自报「医生已确诊」、AI分型与管理员标注均不能充当医生确认。
3. 图片张数、标注任务数、报告份数、临床参考条数使用独立单位；报告内照片不混进白斑图像库。
4. 「当前有效」和「历史投入」分开。撤回授权后图片退出当前可用总量；历史贡献荣誉保留，不以降级阻碍撤回。删除资料后不保留敏感内容，积分记录仅保留实现权利要求所允许的最小事件信息。
5. 影响数是共同参与的数据版本的预计覆盖人数，不是个人疗效或单独归因。多位贡献者的影响人数不可相加，不称「已治愈」或「已帮助康复」。尚未发布的数据不计算预计覆盖。

## 5. 贡献积分与会员成长

建议使用「共建积分 + 共建会员等级」。这是贡献荣誉体系，积分不等于临床可靠性；等级不授予医生权限。

### 5.1 积分建议（设计值，尚未启用）

| 有效贡献事件 | 建议积分 | 发放条件 |
|---|---:|---|
| 一张去重合格图片被采纳 | +10 | 合格且具备对应共建用途授权；同资产只发一次 |
| 完成一张图片的范围核对任务 | +5 | 有明确本人确认记录，任务被采纳；同图同任务不重复 |
| 一组结构化事实得到有效补充 | +3 | 以任务为单位，允许如实回答「不知道」；重复改答不增分 |
| 一份去重体检资料被采纳 | +15 | 已建成该类共建授权与采纳流程后才开放；不奖励新增检查行为 |
| 本人资料获得有依据的医生确认 | +20 | 经医生审核系统验证后，同资料同确认任务只发一次 |
| 同部位完成至少3次合格随访 | +30 | 符合拍摄协议与实际随访周期，形成可比序列；每序列里程碑一次 |

不奖励一次授权点击、重复上传、无意义高频拍照、AI候选生成或重复审核。隐私授权不作为升级任务。稀缺部位贡献可授予「补全拼图」徽章；不以额外积分诱导敏感部位上传。

医生执行审核的积分属于独立审核任务规则，不与普通用户「资料获确认」混淆，也不按“确认白癜风”这种结论奖励。

### 5.2 等级建议

| 等级 | 名称 | 累计积分门槛 |
|---|---|---:|
| Lv.1 | 微光伙伴 | 0 |
| Lv.2 | 添柴伙伴 | 100 |
| Lv.3 | 同行共建者 | 500 |
| Lv.4 | 薪火共建者 | 1,500 |
| Lv.5 | 星火守护者 | 5,000 |

页面显示等级标识、积分、到下一级的差额和进度条。贡献勋章包括「第一份记录」「认真核对」「持续同行」「补全拼图」，每个徽章均有真实触发事件。

首版权益：个人贡献徽章、阶段贡献总结、共建进展订阅（自愿）。不设公开贡献排名，不以积分限制基础记录、授权撤回或既有服务；更多付费/兑换权益不在首版范围内。

### 5.3 账本与状态

- 流程：提交 → 质量/授权审核 → 采纳 → 自动记分。显示「待处理」时不先发有效积分。
- 同一用户、资产、任务、规则版本生成唯一事件键，确保重试与重复修改不多发。
- 被拒收时明确原因与可修正动作；积分不到账可查对应任务，不只展示一个累计数字。
- 规则版本、分值、业务对象和发生时间可追溯；重算/纠错通过追加调整事件，不覆盖旧账。
- 历史存量贡献在有可靠证据时按同一规则补记；无法区分用户确认与AI候选的存量记录不推断成已核对。
- 不因正常撤回授权扣减历史荣誉。欺诈或误记积分与授权撤回使用不同原因和处理流程。

## 6. 共建成果：规模、质量、时间三条线

### 6.1 社区与图像库总览

头部指标：当前有效注册用户数、当前至少贡献一张授权合格图片的用户数、授权去重图片数、带医生参考的病友占比。

说明必须区分：用户账号数、图片贡献者账号数、独立病友/受试者数。一账号可能管理多个病友档案，不能把账号数直接叫作患者数。当前缺少可靠档案关联时，独立病友相关指标显示「待建立关联」。

第二行：同部位≥3次合格记录的病友数、随访跨度、已发布数据版本及本月新增有效贡献。无法可靠统计的项显示原因，不以0替代缺失。

带医生参考占比 = 具有有效医生参考的授权独立病友数 / 有效授权独立病友数；分母必须注明。没有完整身份关联或临床参考链路时暂不计算。

### 6.2 分布与矩阵

默认按「部位 × 医生确认分型」呈现二维矩阵，回应用户希望看到不同部位、不同类型数量的需求；每格显示图片数，可切换独立病友数（有可靠关联时）。

- 分型列：节段型、非节段型、混合型、未分类；另列「尚无医生分型」。临床明确的「未分类」与缺少参考不是同一个状态。
- 正常皮肤与相似疾病单独切换到「对照样本」视图，不将「非白癜风」当作白癜风分型。相似疾病保留具体医生确认类别。
- 部位使用编码与显示名分离的标准字典，并提供左右细分。原用户端、后台部位集合不同，先做显式映射与版本管理；无法映射的进入「待归类」，不强行猜测精细部位。
- 多部位图片指定一个主部位作为可相加的总量口径；多部位明细为非互斥统计，并明确不能直接相加。
- 同一任务只用当前有效标注版本，旧版本不重复计数；图片、区域与病友使用独立分母。
- 高级筛选遵循原方案五维矩阵：部位 × MST肤色 × 设备 × 年龄段 × 成像方式。成像方式包含手机RGB、Wood灯、皮肤镜；拍摄类型（整体/中景/近景）为附加维度。
- 分型、稳定性、进展度不混为一维；如需展示临床阶段，必须来自医生字段。
- 未采集的维度显示「待补充」，不要按AI推断或默认值补齐；不将自报Fitzpatrick替代MST。

目标格集合必须来自版本化采集计划，不以所有取值的笛卡尔积当成必须收齐的目标。

覆盖率 = 目标矩阵中达到预设有效样本门槛的格子数 / 本版本目标格总数。采集目标和门槛由数据负责人配置，页面不虚构「100%全覆盖」或「最大数据库」。

### 6.3 质量视图

除了多少张，还展示已经用户核对、受训标注员复核、医生参考及仲裁的有效量。T1/T2/T3/T4在统计说明中解释，患者页面优先使用可读名称。

这些环节可能重叠；只有互斥的当前状态才能堆叠成漏斗。医生确认、双标一致性与盲测集规模在链路具备后展示；不能用现有 `label_status=labeled` 代替这些指标。

### 6.4 从缺口回到行动

基于真实聚合缺口提示「更多不同部位的记录，会让参考更完整」「持续记录同一部位，有助于补齐变化过程」。用户只补自己知道的信息，可跳过；不要求用户提供医生分型。

有具体可执行的任务时提供「继续核对」「补充事实」「查看拍摄指南」。无任务分配/同意流程时不展示认领他人病例或未经授权的资料。

## 7. 统计可信度与边界状态

- 每组统计返回 `status`（available/unavailable/suppressed）、值、单位、口径版本、统计时间与来源；不可用返回空值和原因。
- 有效零值显示「0」；尚未支持显示「尚未统计」；加载失败给重试；加载中用骨架屏，不让0先闪现。
- 公共结果只发布匿名聚合。稀疏敏感格采用小样本隐藏和互补抑制，避免从总数减出被隐藏值；门槛必须在发布前配置并验证，不能在设计阶段承诺完全匿名。
- 未登录不请求任何个人接口；个人接口只能按当前登录用户取数，不接收可任意指定的他人user_id。
- 个人、公共、积分和临床统计各自失败不阻断整页；公开页不展示他人原图、凭证或检查结果。
- 用户删除/撤回后及时失效当前统计与缓存，展示最新更新时间；历史荣誉不能让被撤回资产继续计入现役库。
- 无可靠影响预测时「预计帮助」显示解释性空态。成熟后依据已发布版本最近三个完整月的去重服务用户计算未来30天预测区间；不足三个月、无版本使用日志或不可覆盖时不预测。方法需校准后上线。

| 内容 | 只读核对结果 | 实施要求 |
|---|---|---|
| 主导航 | `useMainNav.ts`共用导航，当前第四项为`/care` | 改主导航列表新增`/contribution`，隐藏`/care`，保留原页/路由 |

| 个人授权 | `/profile/data`、`api/contribution.ts`、`/api/data-consents`已存在 | 复用状态、范围与撤回入口，不新建平行授权体系 |
| 体检资料授权 | 新授权对象模型目前只说明支持assessment | 不能把图片model_training授权自动扩大到体检报告；扩展后才开放共建计数与积分 |
| 用户事实 | `SelfReportFact`追加式、自报事实为T1 | 取当前版本，不能重复答案累计，不用于临床确诊 |
| 图片统计 | `/admin/image-labels/stats`只有管理角色粗统计 | 新建专门公共聚合接口；用户端不得调用管理员接口 |
| 临床参考 | 现有图片表主要是AI/用户/管理员三来源字段 | 新建认证医生参考事件/依据/版本后，才显示医生确认和临床分型统计 |
| 积分与影响 | 所核对接口与页面中未见相关能力 | 新增账本与幂等计分；版本使用事件与预测后续接入 |

建议服务接口（设计契约，不是已存在接口）：

- `GET /api/contributions/overview`：可公开的规模、质量与统计状态。
- `GET /api/contributions/distribution`：矩阵维度、规范化桶、当前查询分母与抑制状态。
- `GET /api/contributions/me`：本人有效/历史/待处理贡献、积分、等级及影响状态。
- `GET /api/contributions/me/events`：本人分页贡献/计分明细。

前端分层：新`ContributionPage`只编排个人卡、成长卡、成果卡与矩阵组件；`useContributionOverview`、`useMyContributions`负责数据状态；API模块处理请求；统计和计分在服务端完成，不由浏览器根据上传次数计算。

## 9. 分阶段落地与验收

1. 设计确认后先做独立新页、共用导航配置与空态，在测试环境验证。任何演示数据仅允许在明确标注的设计预览中，真实页面默认不填示例数字。
2. 采用独立测试服务验证统计与积分逻辑，使用合成数据覆盖授权撤回、去重、跨档案关联、重复计分和临床来源。共享后端启用前按项目规范说明影响范围，做出可审查实现。
3. 接入可验证的个人统计、公共聚合、积分账本与部位分布。临床参考、报告共建、五维覆盖与影响预测按真实依赖启用，不用错误替代量抢先上线。
