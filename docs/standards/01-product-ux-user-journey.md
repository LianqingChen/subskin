## 一、产品定位与核心价值模型

**SubSkin（白癜风病友的 AI 记录和分享社区）** 致力于用人工智能连接前沿医学研究与患者日常康复管理。产品由三大核心支柱构成闭环：

1. **智能认知中枢（AI 问答 + 小白管家）**：
   - 将晦涩的 PubMed/临床试验文献与临床指南转化为温和、易懂、有据可查的中文解答，并作为全站功能的智能路由器。
2. **数字化病程管理（白斑日记 + 体检解读）**：
   - 通过标准化 24 部位标记、白斑区域辅助分割、前后照片对比与化验单指标解读，帮助病友建立客观、可追溯的个人康复档案。
3. **有温度的互助与共建生态（发现 + 就医经验 + 同行）**：
   - 连接同路病友分享真实护理与就诊经历（不评比医术疗效，专注客观过程与避坑提醒），并通过「同行」可视化展示病友共同建设脱敏影像数据库对医疗 AI 的贡献。

## 三、六大核心用户动线规范（Core User Journeys）

### 3.1 动线一：访客首访与渐进式鉴权动线（Guest-First & Progressive Auth）

```
首屏进入 (/) ──► 免登录直接体验 AI 问答 / 浏览「发现」与「就医经验」 / 查看公开分享报告
                     │
                     ├── 触发低门槛互动（如首条提问、浏览帖子详情）──► 直接放行，不弹登录框
                     │
                     └── 触发私有资产沉淀或社区写操作（保存白斑日记、上传体检单、发帖、评论、点赞、授权数据）
                                     │
                                     ▼
                         平滑唤起 LoginModal（支持手机号验证码 / 密码 / 邮箱登录）
                                     │
                                     ▼
                         登录成功后留在当前页并自动续接刚才的操作（禁止强制跳回首页丢失上下文）
```

- **体验铁律**：
  1. **严禁首屏强制登录墙**：除 `/profile` 等纯私人设置页外，主路由必须支持访客浏览。
  2. **上下文保持**：唤起 `LoginModal` 登录成功后，不得粗暴重置路由，应让用户无缝继续刚刚点击的操作（如继续提交日记或发送评论）。

### 3.2 动线二：AI 智能问答与小白管家全站导览动线（`/` & Floating Butler）

```
用户输入问题 / 点击推荐问题胶囊
        │
        ├── 医学科普与前沿研究问题 ──► RAG 混合检索（向量 + 关键词）──► 流式输出温和解答 + 引用文献卡片 + 底部免责声明
        │
        └── 站内功能意图（如“怎么记录白斑变化”、“哪里看医院经验”）
                │
                ▼
        匹配 SITE_FEATURE_KEYWORDS ──► 回复中内嵌「功能直达卡片」──► 用户一键跳转目标路由（如 /assessment 或 /hospitals）
```

- **体验铁律**：
  1. **流式反馈与状态透明**：等待大模型响应时必须显示平滑的加载指示器（`<i class="ri-loader-4-line animate-spin"></i>`），流式输出过程中支持自动跟随滚动。
  2. **追问引导**：回答结束后提供 2–3 个高相关度的后续建议问题，降低用户提问门槛。

### 3.3 动线三：白斑日记、范围核对与前后对比动线（`/assessment`）

```
进入「日记」(/assessment)
   │
   ├─► 【记一篇新日记】
   │      1. 选择身体部位：24 部位正背面 SVG 木头小人 (DigitalHuman.vue) 点选
   │      2. 上传/拍摄照片：支持原图直接进入（严禁强制正方形裁剪破坏病灶上下文）
   │      3. 白斑范围核对：后台 RGB/CV 分割工作进程自动勾勒初始轮廓 ──► 用户可在 MaskEditor 中手绘增删多边形或微调
   │      4. 补充状态记录：治疗方式、情绪状态、日常备注（可选，不强制繁琐填表）
   │      5. 保存归档：生成本次面积/VASI 评估结果，计入时间轴与「同行」成长环
   │
   └─► 【前后对比与变化报告】
          1. 在时间轴或对比工作台选择同部位的两张照片 / 两次记录
          2. 自动计算面积变化率、色素岛/复色趋势（语义色：好转 emerald / 稳定 amber / 需关注 red）
          3. 生成「白斑变化报告」：支持导出高清 Canvas 海报 (`SkinReportPoster.vue`) 或生成带短效 Token 的公开分享页 (`/share/report/:token`)
```

- **体验铁律**：
  1. **图像完整性**：白斑照片上传时不得强制裁切，必须保留完整部位参照物以便后续前后对比。
  2. **渐进式微提问（`MicroAskCard`）**：在用户完成日记保存后，以非侵入式卡片温和询问 1 个补充问题（如近期是否调整光疗频次），用户可一键回答或随时关闭，**绝不阻塞主保存流程**。

### 3.4 动线四：体检报告 AI 解读动线（`/assessment/exam`）

```
上传化验单照片（血常规 / 甲状腺功能 / 免疫五项 / 微量元素 / 25-羟维生素D）
        │
        ▼
多模态视觉/OCR 提取结构化指标（指标名、测定值、参考范围、上下箭头状态）
        │
        ▼
生成结构化解读卡片：
  1. 异常指标高亮与温和释义（解释该指标与白癜风的潜在关联，避免制造恐慌）
  2. 就诊沟通建议（生成下次复诊可向医生请教的具体问题清单）
  3. 历史化验单归档对比
```

### 3.5 动线五：发现社区与就医经验互助动线（`/community` & `/hospitals`）

```
「发现」社区 (/community)
   ├── 信息流浏览：关注 / 推荐 / 同城（基于 useGeolocation + CityPicker） / 分类筛选
   ├── 图文发布 (CreatePostSheet)：标题 + 正文 + 多图上传 + 分类标签 + 关联白斑报告（需显式勾选公开授权并记入 AuditLog）
   └── 互动交流：点赞、收藏、多级评论、生成帖子分享海报 (PageSharePoster.vue)

「就医经验」子栏目 (/hospitals)
   ├── 医院目录查询：按省份/城市、公立三甲/专科、地址检索医院详情 (/hospitals/:id)
   ├── 医院详情页：官方公开资料 + 就诊前准备问题清单 + 病友真实就诊经历列表
   └── 分享就诊经历 (/hospitals/share)：记录挂号科室、检查项目、治疗过程、大致费用与贴心提醒
```

- **就医经验合规与体验铁律（零容忍）**：
  1. **严禁医疗疗效评比与医生排名**：就医经验模块旨在帮助病友了解「挂号流程、检查项目、花费构成与就诊注意事项」，**不得设置“治愈率排行”、“神医打分”或诱导性医疗广告**。
  2. **社区公约与申诉通道**：页面显著位置提供《就医经验分享公约》与纠错/申诉入口（`CorrectionModal`），所有内容受后台风控（`/moderation` & `/hospital-risk`）保护。

### 3.6 动线六：「同行」共建与数据透明动线（`/contribution`）

```
进入「同行」(/contribution)
   ├── 个人成长环：直观呈现本人连续记录天数、有效影像贡献数与成长徽章
   ├── 全站共建大盘：展示可核验采纳月份柱状图、24 个身体部位有效样本分布
   └── 严格的数据诚实原则：
         - 仅展示数据库真实可核验的统计数据
         - 未知拍摄日期不伪造推测，尚未具备可靠临床参考基线的分型估算明确标注「等待可靠参考数据」，绝不虚构数字
```

## 四、用户体验（UX）与人文医疗交互准则

1. **去焦虑化视觉与文案（De-escalation UX）**：
   - 白癜风病友常伴有较大的心理压力。全站文案应保持**客观、温和、平实、陪伴感**，禁用感叹号轰炸、恐吓式疾病描述或夸大其词的营销话术。
   - 当评估显示白斑面积有所扩大时，使用中性克制的提示（「较上次记录面积有所增加，建议结合近期作息与复诊医嘱观察」），避免使用刺眼的闪烁红警报。
2. **明确但克制的医疗免责声明（Mandatory Medical Disclaimer）**：
   - 所有涉及 AI 回答、VASI 面积评估、体检报告解读、病友经验分享、对外分享落地页与 Canvas 海报的底部，**必须**展示合规免责声明：
     > `本内容仅供病友记录与交流参考，不构成医疗诊断或治疗建议，具体诊疗请遵医嘱。`
3. **空状态与错误状态的闭环引导（Actionable Empty & Error States）**：
   - 任何列表为空时（如尚无日记、尚无同城帖子、搜索无结果），必须提供 RemixIcon 温和插图图标 + 简短说明 + **1 个明确的下一步主行动按钮**（如「记第一篇白斑日记」或「清除筛选条件」）。
   - 网络异常或服务报错时，向用户展示友好的中文提示与「重试」按钮，严禁直接渲染 HTTP 状态码或后端堆栈。
4. **触控与无障碍友好（Touch & Accessibility）**：
   - 所有移动端可点击按钮、Tab、图标链接的最小触控热区不低于 `44px × 44px`（桌面端紧凑工具栏使用 `.control-slim` `32px+`）。
   - 表单输入框、模态框关闭按钮、搜索框均需具备清晰的 `placeholder` 或 `aria-label`。
