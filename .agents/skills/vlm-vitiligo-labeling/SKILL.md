# VLM Vitiligo Labeling（视觉模型标准打标流程）

> 用同一套本地工具让千问、DeepSeek 等视觉模型独立出稿，按审核金标验证涂层，并用可迁移的经验改进后续初稿。
>
> 触发词：视觉模型打标、VLM 打标、千问/deepseek 识别白斑、百炼打标、模型对比打标、金标复现
>
> 关系：本 skill 管「通用视觉模型怎么出稿」；像素级修订、apply、train/bench 仍按 `vitiligo-pixel-labeling`。
> 两者共用金标规范（那边 §2）与度量（`ml/pixel_labeling/metrics.py`）。

---

接手 #182、比较模型或部署日记试测时，先看[白斑分析发布说明](../../../docs/research/2026-11-08-autonomous-vlm-labeling/release-method.md)。其中列出评分口径、旧实验失败原因、证据路径和当前阻塞。

小斑以普通 Dice 为主，另外核对误标、漏标与路由是否实际触发。候选是否补标及局部颜色细化应逐图比较相对固定辅助分割的增益。对照分支的融合结果见[白斑分析发布说明](../../../docs/research/2026-11-08-autonomous-vlm-labeling/release-method.md)。

## 0. 为什么是这个流程（实测结论，改流程前先读）

| 事实 | 证据（182，2026-11-08） | 推论 |
|---|---|---|
| 视觉模型给不出像素级坐标 | qwen3.8-max / 3.7-plus / 3.8-flash 给额发际斑外接框，偏差 30–130px | **不许让模型画多边形/给坐标** |
| 模型擅长「这块是不是白斑」的语义判断 | 三个模型都正确描述了白斑分布 | 让模型对**编号区域**逐个判读（Set-of-Mark） |
| 区域粒度决定上限 | 完美判读时 ±2px Dice：150 区 0.906 / 300 区 0.949 / 600 区 0.978 | 皮肤约 600 区 |
| 判读错误率决定结果 | 600 区：错 0% → 0.979；5% → 0.975；10% → 0.949；15% → 0.933 | 该模拟可用于诊断区域判读误差 |
| 单纯相信判读会把错误原样画出来 | 10% 错时直接用判读 0.870 | 用**交叉拟合颜色模型**把错判找出来（10% 错时找出 29/45） |

**场景适用性（模拟，见 `ml/vlm_labeling/RESULTS.md`）**：均匀切区适合大片白斑（白斑 ≥10% 皮肤：182/186/199 完美判读 ±2px 0.97–0.98）；**小斑/卫星斑为主（如 207 腹部 1.65%）不适用**——完美判读也仅 0.71，3% 错判即崩。此类图待实现「候选块」路线（白度候选逐块判读），在此之前走 `vitiligo-pixel-labeling` 的 `candidates`。

## 1. Hard rules

1. **隐私闸门**：日记照片（`/api/files/serve/vasi/...`）是 L3 数据，外发任何模型前必须有照片所有者对**本次处理**的授权（STD-03 §5.1），用 `--owner-consent "<谁、何时、范围>"` 记录，审计写入 `data/labeling_work/vlm_external_audit.jsonl`。公开导入图（`label-source:`，PMC CC BY/CC0、Commons）可直接用。分析授权 ≠ 训练授权。
2. **出稿使用原图、原图派生视图和冻结的通用规则**。当前目标金标、历史答卷、其他模型答案留在推理上下文之外。对照实验采用其他公开病例作参考时，记录许可、来源及标注版本。涂层冻结后用本地 `score`/`learn` 对照指定金标版本。独立复现与未参与规则开发的新图首跑分别记录。
3. **后台初稿仅用于 pending**。本流程将冻结涂层和标签候选导出到工作区。加载前核对当前任务原图和涂层。后台的像素流程 `apply` 按其决策重算涂层，VLM 审核包的加载需保留导出的类别图。
4. **模型只给代码，不给坐标**。像素一律由本地 `fuse.py` 产生，保证可重放（`replay`）。
5. rubric 是唯一的「模型知识」入口：经验只写进 `rubric.md`（带来源图号），不要散落在 prompt 代码里。

## 2. 标准流程（`ml/vlm_labeling/protocol.py`）

```
P0 隐私闸门 → P1 本地切区域(SLIC，皮肤细/非皮肤粗) → P2 通读(部位、此人正常色/白斑色、每块白斑在哪)
→ P3 分块判读(原图放大 + 编号图，每个编号一个代码) → P4 融合(交叉拟合颜色模型 + 门控；皮肤/背景同法细化)
→ P5 复核(颜色强烈反对的区域放大再问) → [P6 审稿：默认关闭，实测有害] → P7 存决策(可重放)
```

- **代码**（定义见 `rubric.md`）：`L` 白斑、`N` 正常皮、`B` 背景、`O` 遮挡、`X` 不可读、`M` 混合（程序按颜色切开）、`U` 不确定。
- **协议 v3：一张图跑 3 次（`--regions 600/800/1000`）再 `vote`**。单次运行波动大（182 白斑占比 37–44%），3 次像素投票稳定优于最好单次（182 ±2px 0.928→0.933，263 0.860→0.874）。当前实现的白斑和可见皮肤均需严格过半。**比较两版 rubric 也必须用投票结果，不要用单次。**
- 自动投票要求同一个图片任务的独立运行目录。带有输入清单的运行还会检查原始 RGB 指纹和分区文件。使用 `auto` 时，全批次使用同一份冻结规则，可用 `--rubric` 指定候选规则。任一预定密度缺结果会留下 `incomplete.json`，可按其中的子进程日志复查。可选锚定失败会记录在 `auto.json` 的 `failed_anchors` 中。
- **P5b 锚定复核（`anchor` 命令，可选，非默认）**：用此人自己最确定的正常皮/白斑区作色卡复核边界区。单用必过标；与原始运行一起投票时 182 达 Dice 0.915 / ±2px 0.953、185 提升，但 263（深肤色小斑手）回归失败，故不进默认流程。
- **百炼 token-plan 并发上限**：同时 8 个任务（约 32 路请求）会被限流到几乎不出结果；同时最多 2–4 个任务。
- **P6 审稿默认关闭**（`--review 1` 可开）：2026-11-08 实测模型看红色填充稿会大量改错（qwen 199 ±2px 0.830→0.723，deepseek 186 0.861→0.800）。
- **改融合参数前先用 `verdicts_from_log` 在已有真实判读上离线重算**（不花模型调用）；门控/覆盖/自清洗参数在 3 组真实判读上已证明不是瓶颈。
- **P4 门控融合**：每个区域默认听模型的；若「没见过该区判读」的颜色模型（3 折、按区域分组）对该区的平均白斑概率与判读相反超过 0.35，就按颜色逐像素决定；同意的区域内只有颜色近乎确定（<0.1 或 >0.9）的像素才翻转；`M/U` 按颜色。
- `run --resume <运行目录>` 会继承未指定的密度和复核设置，并核对 `run_inputs.json` 中的任务、模型、原始 RGB、规则、分区和像素特征。旧运行目录可以续跑，从新建清单的这次运行起记录输入指纹。
- 百炼返回月额度耗尽时，命令以状态码 75 退出。自动运行停止派发新分支，`incomplete.json` 记录已启动和待处理的分支。额度恢复后，单次运行用 `run --resume`，自动运行用 `auto <图号> --model <原模型> --resume "$AUTO_DIR"`。自动续跑沿用原分区计划和规则快照，保留已完成的分支与参照复核，已完成答复按请求指纹复用。
- 每步产物在 `data/labeling_work/<id>/vlm/<model>-<时间>/`：`p4_fuse.jpg`、`p5_recheck.jpg`、`p6_review0.jpg`、`labels.npy`、`decision.json`（区域参数 + 每区代码 + rubric 版本）、`exchanges.jsonl`（全部 prompt/回复，不含图片）。

## 3. 正循环（每张新金标都走）

```
run（新图，模型没见过金标）→ score：记「首跑分」（真实能力）
→ learn：区域级准确率、错判清单、错判拼图、疑似金标错误拼图
→ 人/agent 看拼图归因 → 写 rubric 经验条目 E-<图>-<n>（版本号 +1）
→ 在「历史全部金标」上重跑 → 不降才接受新 rubric（回归）
→ 下一张新图
```

- **正循环必须有金标锚点**：无金标的自评（判读与颜色模型的一致度）不能预测准确率（37 次运行相关 ≈ 0.07；系统性欠标的模型自洽度反而最好）。所以循环是「AI 投票初稿 → 人工修边成金标 → learn 归因 → 改 rubric/流程 → 全部金标回归」，不能省掉人工金标这一步。
- **归因落点**：① 模型看错了且规律可说清 → `rubric.md` 经验条目；② 颜色模型切错（判读对、像素错）→ `fuse.py` 参数，需在全部金标上 `simulate` 回归；③ 区域切得不对（一区跨两类）→ `regions.py` 参数；④ **颜色或模型提示差异** → 列入 `gold_suspect`。用 `adjudicate --referee none` 在本地生成差异图和覆盖统计，由审核人按原图逐处确认。
- **区分判读和融合的误差**。完整涂层冻结后，用 `simulate <图号> --flip 0` 做理想区域判读对照，并分别统计实际模型对已审核纯白斑区和纯正常皮肤区的识别率。对照在同样的区域和融合下复算。对已审核像素至少 99% 同类的区域，分别记录判读类别和最终输出类别。跨密度按原图像素去重，核对反复漏标的位置是否一致。用剩余像素误差检查分区与融合；模拟产物只用于归因。
- **整图自检覆盖率**。在涂层和自检答复都已冻结后，用金标统计自检列出的区域覆盖了多少实际漏标和误标。分别按图上可见分块框和分块所属区域计数。#182 的三档对照中，DeepSeek 700 密度未列出待查分块，该阶段仍有 50,507 个金标白斑像素漏标。固定复核面积后，优先选自检分块，在 #182 两款模型的六组对照中，10% 面积预算下有五组覆盖的白斑漏标减少、一组持平。公开 #201、#263 的四组对照在同一预算下有三组覆盖下降。优先自检分块的排序暂留实验，最终以逐像素评分和审核证据验收。复算见 `subskin_audit_cold_helper_self_review.py`。
- **逐像素验收**。在原图网格分别报告白斑、正常皮肤和总可见皮肤 Dice，附每类误标、漏标与全部差异像素数。`lesion_dice_tol2` 作为边界诊断。区域准确率以所有已知 N/L 区为分母，并报告模型的有效回答覆盖率。
- **#182 独立复现**。千问和 DeepSeek 分别做完整冷启动复测，保存各自的真实百炼回执与冻结涂层，核对输入、版本、参数和响应 ID。每次逐像素匹配后台已审核参考。若保留少量差异，逐处记录普通 RGB 上清楚、充分、经审核确认的证据，并同时报告原始参考和确认修订后的结果。两款模型各自通过后，再测试下一张用户照片。验收依据见 [白斑分析发布说明](../../../docs/research/2026-11-08-autonomous-vlm-labeling/release-method.md)。
- **标签按字段验收**。身体部位、可见外观和临床候选各自保留来源与审核状态。出稿前核对初判提示是否明确要求标准外观词条、可见部位与白斑受累部位。对已运行的旧提示，用同模型在独立会话中凭本次原图和同图定位视图补答，并把补答回执关联到相同原图和模型的审核包。原始外观描述和标准化补答都保留。用当前批准版本的人工字段核对可评分内容。仅有单个批准部位时，报告模型是否覆盖该部位，并将其他部位和缺参考的外观字段列为待审核。单张 RGB 的临床候选保留未确认状态。涂层一致、模型共识或标签格式合格均不能证明标签准确。实例和回执核对见 `subskin_workflow_acceptance_replay.py`。
- **涂层差异复核**。将已冻结的类别图与指定金标逐像素对照，按类别变化和连通性记录差异区域。审核包的差异索引覆盖金标有标注的全部差异像素，并提供各类中较大的区域裁片供人工核对。先看无涂层原图，再比较模型和金标边界。只有原图证据充分且经审核确认的差异才可作为金标修订。
- **冷启动回执验收**。多分区复现目录可用 `PYTHONPATH=. .venv/bin/python docs/research/2026-11-08-autonomous-vlm-labeling/subskin_audit_private182_cold_repeats.py <首轮目录> <复测目录>` 核对。工具读取各轮的回复到像素回放证明，并重新核验实际百炼响应 ID、原图、请求图像指纹、参数和最终涂层。工具报告原批准金标的验收结果。#182 如有少量修订，用同一脚本的 `--describe-revision <提交号> --out <证据.json>` 列出所有变化的连通区域。审核人对照普通光原图和两版涂层，为每处填写 `rgb_observation`，说明原边界错误及修订依据。审核人批准该修订时，在后台审核备注写入 `rgb-evidence-sha256=<证据文件的 SHA-256>`。验收时传 `--reviewed-submission <提交号> --rgb-evidence <证据.json>`，核对原图、每处变化和批准记录，并分别评分。两款模型的冷启动涂层都通过后，仍需按字段完成标签验收。可提炼经确认的通用判读规则，并在留出的公开样本回归。#182 的证据和具体位置仅用于评估。
- **先核对候选是否覆盖漏标**。用冻结涂层对照金标，将漏标按可见皮肤范围内外、是否有白斑判读支持分别计数。已有判读未覆盖的区域，需要新的原图证据或候选生成方法。计数用于复盘，目标金标不得用于选区。
- **跨模型融合回归**。两模型独立出稿后，可用同一组公开金标评估分歧像素上的选择器，并分别报告每个模型和融合结果。按来源留出评估图，单独统计两模型共同错判的像素。融合结果的分数与 #182 各模型的独立验收分别记录。
- **复核候选的回归**。固定初稿、原图视图、区域编号和预算，先冻结候选，再用真实答复复算三层涂层。分别报告候选覆盖、实际纠正、新增错标和重复判读差异。用公开图按来源留出对照，保留小斑、深肤色和光照不均的难例。具体规则与历次结果见[白斑分析发布说明](../../../docs/research/2026-11-08-autonomous-vlm-labeling/release-method.md)。
- **整图投票后评分**。`auto` 的每个区域密度分支先生成预测，不读取金标评分。整图投票和细化完成后，`auto.json` 才记录批准参考的提交号、修订版本和投票前后各涂层分数。单独生成未评分的初稿时可用 `run --no-score`。
- **区分重建与复测**。使用历史答复重放只验证本地工具生成同一涂层。`replay` 遇到输入校验失败或涂层差异会以非零状态退出。每次独立复测都用新的模型会话和真实响应。
- **标签**。分别记录图中可见部位（`body_sites`）和可见白斑所在部位（`affected_body_sites`），再记录可见外观类型。审核包保留每次原始外观描述、已规范的词条和各候选的支持轮数，供审核时核对。临床分型单列，普通光单图候选保留 `unconfirmed`、`image_only`、`review_required: true`。 #182 用标准结构化提示补测后，两款模型均输出白斑部位与外观词条，临床分型均为未确定。胸部是否受累存在模型分歧，审核包保留各自候选。

## 4. 工具与验收

按任务阶段选择命令。对照不同模型时，每款模型各自生成整图结果，使用相同原图、分区方案和标签口径。规则回归使用已冻结的真实判读，独立复测需要本轮的新回执。

| 阶段 | 输入 | 保存和核对的结果 |
|---|---|---|
| 初稿 | 本次获准原图、指定视觉模型、冻结规则 | 原图指纹、规则快照、每区代码、三层涂层、标签候选 |
| 独立复测 | 同一原图与流程、各模型新会话 | 逐模型回执、原图视图与参数、整图涂层重建 |
| 金标对照 | 冻结涂层、已批准提交及修订版本 | 三层 Dice、误标和漏标、逐像素差异索引 |
| 人工复核 | 干净原图、AI 涂层、金标、标签候选 | 每处差异的原图证据、审核决定、标签缺项 |
| 规则回归 | 同一批来源留出的已审核图、基线与候选 | 每图每模型对照、错标变化、三层是否退步 |

```bash
cd /root/subskin
.venv/bin/python -m ml.vlm_labeling run 199 --model qwen3.8-max          # 公开图
.venv/bin/python -m ml.vlm_labeling run 182 --model sim:0.1              # 离线模拟（10% 错判），测流程用
# 将 RUN_DIR 替换为上一步生成的目录
.venv/bin/python -m ml.vlm_labeling score "$RUN_DIR"
.venv/bin/python -m ml.vlm_labeling learn "$RUN_DIR"
.venv/bin/python -m ml.vlm_labeling replay "$RUN_DIR"
.venv/bin/python -m ml.vlm_labeling simulate 182 --flip 0 0.05 0.1       # 判读准确率 → Dice 曲线
```

- 研究 CLI 的既有百炼归档使用 Token Plan 端点。模型需支持 `image_url` 并能覆盖编号区域，服务商和模型按本次处理授权核对。日记试点接入单独的百炼按量接口，配置见交接文档。
- 千问 `qwen3.8-max` 与 DeepSeek `deepseek-v4.1-flash-1017` 均已完成视觉调用。两款模型的 #182 独立复现仍待验收。
- 百炼 `qwen4-max-preview` 已纳入实验对照。记录请求型号、返回型号及推理档位，按相同原图、分区、像素工具和评分阶段复算。预览对照的结果见[白斑分析发布说明](../../../docs/research/2026-11-08-autonomous-vlm-labeling/release-method.md)。
- 完成的单模型运行可用 `python -m ml.vlm_labeling.review_packet from-run "$RUN_DIR" "$REVIEW_DIR"` 导出审核包。导出前核对后台规范化原图，按保存的区域判读重建涂层。标准多密度自动运行可用 `python -m ml.vlm_labeling.review_packet from-auto "$AUTO_DIR" "$REVIEW_DIR"`，按原票和参照复核票重建涂层。每份初判标签附运行目录名、分区密度和判读文件的 SHA-256，便于审核时追溯。旧 v4 归档可能已经应用边界细化，导出时分别核对原始投票与细化结果。只有逐像素一致才导出。已独立核验的冻结涂层可走按指纹导出的入口。其他已冻结的整图结果可传入类别数组及其 SHA-256、原图 SHA-256、模型和该次初判记录。输出 `labels.png`、白斑 `lesion.png`、正常皮肤 `normal_skin.png` 和总可见皮肤 `total_skin.png`，用于本地逐层核对和人工审核。用 `python -m ml.vlm_labeling.review_packet check <图号> <审核包目录>` 核对后台原图、三张涂层和当前任务状态，并报告现有日记初稿读取会改变的类别与像素数。标签候选随包保留，后台现有初稿图层接口只返回涂层。
- 规则版本回归用 `python -m ml.vlm_labeling compare-regression <基线清单.json> <候选清单.json>`。清单顶层记录 `model`、`workflow_sha256` 和 `cases`。每个病例记录 `task_id`、`source_rgb_sha256`、`gold_submission`、`gold_revision`、`labels`（冻结的 `.npy`，可相对清单路径）和 `labels_sha256`。两份清单应覆盖同一组病例，引用各自实际完成的整图结果。工具读取当前已批准快照，逐张检查三类涂层 Dice、已知像素错标和未判定像素，退步时返回非零。报告的 `pixel_changes` 按金标类别、旧类别和新类别列出像素变化，帮助找到修正、新增错误以及类别改变后仍然错标的像素。候选至少改善一项且各项无退步时，`improved_without_regression` 为真。通过后仍按 #182 独立复测和审核要求验收。
- 多模型共用规则用 `python -m ml.vlm_labeling compare-regression-suite <基线套件.json> <候选套件.json>`。套件顶层的 `models` 将完整模型 ID 映射到上一条的清单路径，路径相对套件文件解析。基线套件应预先固定各模型的验证病例，保留已知难例。候选需覆盖相同模型和各自相同病例，并且至少有一项改善、任一病例的任一验收指标均无退步，命令才返回 0。报告列出各模型仍有逐像素差异的病例。整图独立复现继续按冷启动回执验收。
- 运行摘要在 `ml/vlm_labeling/runs/`。用 `bench <图号...> --model <模型> --rubric <候选规则>` 记录单次判读的回归诊断。比较时核对每图的金标提交和修订版本，并检查白斑、正常皮肤、总可见皮肤的误标和漏标。整批评分状态、缺金标与运行失败都写入 `bench.jsonl`。正式验收按上面的完整投票和独立复测执行。模型对比与历史见 `ml/vlm_labeling/RESULTS.md`。
