## 1. 目标与约束

**目标**：把「白斑对比」（当前挂在报告模块 `/report`）融合进测评页 `/assessment` 的历史功能模块，让用户在一个页面顺畅完成：
1. 单次白斑测评（拍照 → AI 分析 → 结果）
2. 跨时段多张照片/多次评估的对比分析（轻量快速对比 + AI 深度对比报告）

**约束**：
- 测评页不能臃肿：3 步向导的专注体验必须保留
- 两种能力（单次测评 / 跨时段对比）要让用户一眼可感知，尤其移动端
- 命名遵守 site-modules.json 单一事实来源；icon 用 RemixIcon；共享后端改动必须 additive

## 2. 现状盘点（探索结论）

### 2.1 页面与路由

| 页面 | 路由 | 职责 |
|---|---|---|
| AssessmentPage | `/assessment` | 白斑测评（3 步向导）+ 体检解读 tab；评估历史在桌面左侧栏 / 移动底部抽屉 |
| ReportHubPage | `/report` | 白斑对比入口卡 + 健康报告（上周/上月）+ 历史报告列表 + 多选提炼 |
| SkinReportCreatePage | `/community/reports/new` | 白斑对比报告生成页：上传照片 + 从照片库按日期分组多选（≤4）→ 异步 AI 报告 |
| SkinReportViewPage | `/community/reports/:id` | 对比报告详情（配对识别、像素配准、热力图、时间轴堆叠、分享海报） |
| VasiComparePage | `/assessment/compare?ids=` | 轻量 2 条评估对比（滑块 + delta + 病灶追踪），即时渲染 |

### 2.2 数据层事实（关键）

**两套平行的"历史"体系：**

| | VASI 评估记录 (`VASIAssessment`) | 照片库 (`PostImage`) |
|---|---|---|
| 来源 | 测评页 3 步向导 | 分享/日记发布、白斑对比页直接上传（存为**私有帖**） |
| 内容 | image_url、body_site、评分、分期、画布/掩膜层 | image_url、body_site、capture_date、可选 `vasi_assessment_id` 关联 |
| 用于 | 评估历史面板、vasi-compare、周报/月报 | **对比报告唯一原料**（`POST /skin-reports/comparison` 只吃 image_ids） |

**已有但未被利用的打通基础：**
- `spot_compare.py` 的 ref 体系同时支持 `pi:{post_image_id}` 和 `va:{vasi_assessment_id}`，且 `va:` 解析信息更丰富（canvas_json、掩膜层、auto_finalized）
- `spot_compare.iter_user_photo_timeline(db, user_id, body_site)` 已实现**跨两套体系的统一照片时间线**，周报/月报已在用（skin_report.py:1094、1523）
- 仅手动对比报告端点未接入统一时间线 —— 打通成本集中在服务层参数化，不动 schema

### 2.3 三个"对比"入口现状（用户心智混乱的根源）

1. 测评历史多选 2 条 → **快速对比**（vasi-compare，即时）
2. 报告模块白斑对比卡 → **对比报告**（SkinReportCreatePage，异步 AI）
3. 报告模块历史报告多选 → **提炼对比**（synthesize，报告级）

## 3. 问题诊断

1. **正常用户路径断裂**：「不同时间拍照测评 → 形成历史 → 多选历史 → 对比报告」目前走不通。测评照片不进照片库，对比报告选不到；用户必须去报告模块重新上传照片或翻日记。
2. **功能归属错位**：白斑对比的输入是评估照片、用途是看病情变化 —— 属测评域；挂在「报告」模块（主题是周期性汇总）违背直觉。
3. **移动端可发现性弱**：评估历史藏在上角小图标 → 底部抽屉；用户不知道测评页能做跨时段对比。
4. **三个对比入口、两种结果形态**并存，无引导区分。

## 4. 候选方案评估

### 方案 A：多选历史评估 → 汇总分析 → 对比报告（用户提案 1）

| 维度 | 评估 |
|---|---|
| 心智匹配 | ★★★ 完全符合"评完即得历史，多选即得对比"的自然路径 |
| 交互成本 | ★★★ 复用历史面板现有多选模式，改动小 |
| 可发现性 | ★★ 多选仍藏在面板里，移动端发现性没有本质改善 |
| 前置条件 | 需后端支持（comparison 接口收 vasi_ids）——底层已具备，成本可控 |

### 方案 B：历史评估放功能卡片下方（用户提案 2，仿体检解读）

| 维度 | 评估 |
|---|---|
| 可发现性 | ★★★ 一眼可见 |
| 与向导冲突 | ✗ 3 步向导是全屏专注流程（Step1 相机、Step2 轮廓画布），改"卡片+长列表"滚动页破坏专注体验；"默认展开最近5次"在移动端把拍照入口推出首屏 |
| 重复 | ✗ 桌面已有左侧历史栏，同屏两份历史；页面变长 —— 正是"臃肿"担忧的来源 |
| 结论 | 整体照搬不可取，但其核心诉求（可发现性、筛选、醒目入口）必须吸收 |

### ✅ 方案 C（推荐）：A 的交互骨架 + B 的可发现性补救

- 3 步向导**不动**（单次测评体验零变化）
- 历史面板升级为"历史与对比"中心（A 的多选 → 对比报告）
- Step1 下方加一条**最近评估横滑条**（B 的可发现性，但不铺开成列表）
- 后端打通 vasi_ids（A 的前提）
- 报告模块瘦身，职责回归"汇总与报告管理"

## 5. 方案 C 信息架构

```
测评 (/assessment) —— 评估域：单次测评 + 历史 + 对比
├─ Tab: 白斑测评 | 体检解读（不变）
└─ 白斑测评
   ├─ 3 步向导（不变）
   │   Step1 拍照/选照 + 部位选择
   │   │    └─ 🆕 「评估历史」横滑条（lg:hidden，见 5.1）
   │   Step2 AI 轮廓编辑（不变）
   │   Step3 结果（sparkline 趋势已有）
   │        └─ 🆕 同部位存在历史时，显示「与上次评估对比」快捷按钮
   ├─ 评估历史面板（桌面侧栏 / 移动抽屉）—— 升级为「历史与对比」
   │   ├─ 🆕 部位筛选 chips
   │   ├─ 多选模式升级：
   │   │     主按钮「生成对比报告」（≥2 条，≤4 条）→ 异步 AI 报告
   │   │     次按钮「快速对比」（恰好 2 条）→ 现有 vasi-compare（保留）
   │   └─ 🆕 面板底部「补录老照片」入口 → SkinReportCreatePage（保留，换入口）
   └─ 对比报告结果 → SkinReportViewPage（复用现有详情页）

报告 (/report) —— 汇总域：周期汇总 + 报告管理
├─ 健康报告（上周/上月）（不变）
├─ 历史报告列表（新生成的对比报告也在此沉淀）（不变）
├─ 多选历史报告 → 提炼对比（不变）
└─ 「白斑对比」入口卡 → 移除，换为过渡引导（见 5.5）
```

**职责一句话**：测评页回答"我的白斑现在怎么样、和过去比怎么样"；报告页回答"帮我汇总一段时间的全部情况"。

### 5.1 Step1「评估历史」横滑条（移动/平板可发现性核心）

- 位置：Step1 主卡片下方，`lg:hidden`（桌面有常驻侧栏，不重复）
- 形态：标题行「评估历史」+（有 ≥2 条同部位记录时的「对比」快捷按钮）；横滑 mini 卡：部位、日期、评分、趋势箭头；末位「全部」卡
- 交互：mini 卡 → 评估详情；「全部」→ 展开侧栏/打开抽屉；「对比」→ 自动带入最近 2 条同部位进快速对比
- **空态文案承担教育职责**：「拍照测评后，可在这里对比不同时期白斑的变化」—— 这是让用户知道"此处既能单次测评、又能跨时段对比"的关键触点
- 新组件：`components/tracker/AssessmentRecentStrip.vue`（≤200 行），数据复用 `useVasiHistory`

### 5.2 历史面板升级（AssessmentHistoryPanel）

- **部位筛选 chips**：`loadHistory(reset, bodySite)` 后端已支持，UI 化即可（全部/手/面/躯干…，取 BODY_SITES）。**不加时间筛选**：记录按时间倒序 + 分页已够用，日历筛选是臃肿来源（记录量大时 Phase 3 再议）
- **多选双动作**（关键区分，避免"三个对比"再度混乱）：
  - 「生成对比报告」主按钮（primary）：调 `POST /skin-reports/comparison`（新 vasi_ids 参数）→ 跳报告详情页轮询，1-2 分钟异步
  - 「快速对比」次按钮（ghost）：仅恰好选中 2 条时出现 → 现有 vasi-compare 即时滑块对比
  - 按钮文案即引导：深度分析（AI 报告，可分享）vs 立即看图（滑块对比）
- **跨部位多选处理**：与 SkinReportCreatePage 同规则 —— 提示"建议同部位对比"，用户可指定统一对比部位（沿用 `body_site` 参数）或取消选择
- **多选上限 4 条**（对齐报告生成能力）
- 面板底部「补录老照片对比」入口：进入 SkinReportCreatePage（保留其上传 + 元数据编辑 + 排序能力，服务老照片补录场景）
- 组件行数：现 209 行，升级后预估 ~380 行，仍在 400 行红线内；筛选 chips 可拆 `HistorySiteFilter.vue` 兜底

### 5.3 Step3「与上次评估对比」快捷入口

- 完成一次测评 = 对比意愿最强的时刻
- 条件：当前部位存在 ≥1 条历史评估 → 显示按钮 → 直接进快速对比（最近 2 条同部位）
- 若用户想要深度报告，从对比页引导「生成 AI 对比报告」（vasi-compare 页加一个次级按钮）

### 5.4 对比报告的沉淀与回看

- 生成的对比报告进入报告模块「历史报告」（已有行为，无需改动）
- 评估详情页（VasiDetailPage）与 vasi-compare 页可后续加「已生成对比报告」关联（Phase 3，非必需）

### 5.5 报告模块瘦身与过渡

- ReportHubPage 顶部「白斑对比」卡移除；**保留一个版本的过渡引导**：「白斑对比已移至测评页，去对比 →」（避免老用户迷失，观察一个版本周期后移除）
- SkinReportListPage 已废弃不用（607 行，路由未挂载）→ 本次不处理，另开 cleanup 任务

## 6. 后端打通设计（additive，共享后端红线内）

**原则：不改 schema、不自动建 PostImage、原 image_ids 路径零改动。**

1. `ComparisonReportRequest` 新增可选字段 `vasi_ids: Optional[List[int]]`（与 `image_ids` 至少一个非空；vasi_ids 限 2-4 条）
2. `generate_comparison_report(...)` 支持 `vasi_ids` 入参：
   - 校验归属（user_id）与部位一致性（或用户指定统一 body_site）
   - 按 assessment_date 排序，将每条评估映射为对比点（image_url、日期、部位、评分、分期）——`spot_compare` 的 `va:` ref 解析已就绪，且比 PostImage 点更丰富（画布/掩膜层）
   - refs 用 `va:{id}`，`compare_pair` / 配准 / 时间轴管线全部复用
3. 前端 API：`createComparisonReport` 增加 `vasi_ids` 可选参数
4. ⚠️ 上线流程：后端改动立即影响正式环境（共享后端）——虽为 additive，仍需先在 staging 充分验证、并按零容忍流程告知用户
