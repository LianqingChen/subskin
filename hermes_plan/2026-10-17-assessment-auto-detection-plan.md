# 记录页白斑自动识别：审查、实测与最终方案（2026-10-17）

> 目标：用户拍照/上传后，系统自动给出白斑范围与占比，用户只做"确认/点一下修正"，不再手绘皮肤和白斑两层蒙版。
> 实验代码与图：`tmp/vit_eval/`（exp.py / exp2.py / exp3.py，up_a.jpg、auto_body.jpg；逐张用户照片副本已按隐私要求删除）。实施进度见同日 task_plan。

## 1. 结论

1. **现在根本没有"识别模型"**。registry `enabled:false`、无权重，所有任务走 `inference._interactive_reference` 的固定 HSV/YCrCb 阈值；且按设计白斑层恒为空，候选全进橙色"待核对"，所以用户只能自己画。
2. **最大的单点错误是"皮肤"识别**：米色墙、卡其 T 恤、地板被当成皮肤，白斑候选也落在墙和衣服上。换成预训练人体解析（MediaPipe multiclass）后皮肤 IoU 从 0.35~0.51 → **0.85~0.89**。
3. **零训练的每图自适应色素模型（v2）**比现网好 2 倍以上，可直接作为"预填白斑初稿"；但光照复杂、体表弯曲处仍不稳，**上限有限**。
4. **真正"精准"必须靠专用分割模型 + 合格金标准**。文献中同类模型（中国 III–IV 型肤色）内部 Jaccard≈0.79、外部≈0.69，与人手重复标注一致性（本库实测 0.78）同量级——这是现实的天花板，不是 100%。
5. 现有"金标准"本身很粗：14 条用户确认掩膜全来自同一用户、全是面部、仅 ~6 张不同照片；手绘为大色块（含眼睛、背景树林），同图重复标注占比相差 ±5pp，甚至同图 19% vs 87.5%。**用它无法证明"精准"**，必须先建标注基准。

## 2. 实测（系统内现有白斑照片）

### 2.1 面部 8 张（同图重复标注一致的记录；对照=用户确认掩膜）

| 方案 | 皮肤 IoU | 白斑 IoU | 精确率 | 召回率 | 占比误差（pp） | 耗时/张 |
|---|---|---|---|---|---|---|
| 现网 `infer_rgb`（今日代码重跑） | 0.30~0.93（多数 0.35~0.51） | **0.16** | 0.29 | 0.30 | **−19.7** | 0.3s |
| v2：人体解析 + 光照校正 ITA + Otsu + GrabCut | **0.85~0.89** | **0.37~0.43** | **0.69** | 0.53 | **−7.2**（绝对 8.2） | 1.5~2.5s |
| v3：1 正 1 负点击传播（颜色特征） | 同上 | 0.35（波动大 0.18~0.57） | – | – | – | 2s |
| v3 + SAM 图像嵌入特征 | 同上 | 0.38 | – | – | – | 7~10s |
| 参考：同一用户对同一照片重复手绘 | 0.93~0.97 | **0.77~0.82** | – | – | ±5 | – |

说明：IoU 偏低有相当部分来自对照掩膜本身是"大块涂抹"（v2 边界更贴合真实色差，但被对照判为漏/错）。目视上 v2 已准确找到额头眉上条带、鼻口下巴中央区、颈部斑块；主要漏检在鼻翼/鼻侧阴影里的白斑。

### 2.2 身体部位（手、躯干、小腿、颈肩、背）

- 现网：皮肤蒙版吞掉墙面、地砖、浴室门、拖鞋，候选大量落在背景（`tmp/vit_eval/up_a.jpg` 中列）。
- v2：皮肤只覆盖身体；小腿、颈肩、背部大斑块定位基本正确，但手背/躯干在光照不均时出现大片过检（右列）。

### 2.3 附带发现

- 对比库内 9 月存档候选：M1（b7f5638）之后重跑，`174` 号整张图都被判为皮肤（皮肤占比 0.73→1.0），182 号候选 IoU 0.33→0.11。**M1 的"皮肤分母纳入浅色区域"疑似造成回退**，建议优先复核。
- 子代理代码审查提示：AI 粗定位（VLM）任务在 `subskin-rgb-worker` 内执行，而该 unit 配了 `IPAddressDeny=any`，外呼大概率被拦（未实测验证）；历史离线 VLM 评测 0 像素。
- DINOv2 预训练特征未测试：通过 torch.hub 拉取远程代码被本机权限策略拒绝。

## 3. 根因

| 层 | 问题 | 证据 |
|---|---|---|
| 皮肤 | 固定肤色阈值无法区分"米色背景/衣服"与皮肤；白斑本身又不在肤色范围内 | 皮肤 IoU 0.35；墙面候选 |
| 白斑 | 局部众数参照 + 固定阈值：大面积白斑时参照被拉向白斑；光照梯度、阴影被当色差 | 召回 0.30；左右脸被切开 |
| 策略 | 候选永远进 uncertain、白斑层恒空 → 必须手画 | inference.py:57 docstring、policy.py:57 |
| 数据 | 无合格金标准、无训练集，模型训练链路（ml/rgb_segmentation）从未运行 | 14 条单用户面部标注 |
| 物理 | RGB 照片下早期/三色白斑与正常皮肤色差极小，伍德灯才是临床金标准 | 鼻侧阴影漏检 |

## 4. 最终方案（分层，逐层可上线）

```
拍摄引导/质量门 → [L1 皮肤解析] → [L2 白斑初稿] → [L3 一点即改] → 确认 → 标注回流 → [L4 专用模型] 替换 L2
                                                                       ↘ [L5 纵向对齐与变化判定]
```

### L1 皮肤解析（替换 build_skin_mask）—— 收益最大、风险最小
- MediaPipe `selfie_multiclass_256x256`（16MB，Apache-2.0，CPU 约 0.1s）取 face-skin + body-skin；FaceLandmarker（已在 `data/models/mediapipe/`）剔除眼、眉、唇；头发/衣服/背景类别直接进 excluded。
- 近距离局部特写（解析器置信低时）回退：中心点 + SAM（已有权重），再回退旧阈值。
- 验收：标注基准上皮肤 IoU ≥ 0.85；背景误入皮肤 < 2%。

### L2 白斑初稿（零训练，替换 segment_lesions_edge_aware 作为默认）
- 在 L1 皮肤内：用"非白斑皮肤"拟合二次多项式光照面 → 校正 L*、b* → 计算 ITA（个体类型角，越大色素越少）→ Otsu 分两类 → 迭代 3 次 → GrabCut 贴边 → 形态学清理。
- **策略变更**：高置信像素直接写入**白斑层（粉色预填）**，仅阈值附近的窄带进 uncertain；用户看到的是"已经画好的初稿"，默认动作是"确认"。
- 质量自检：两类 ITA 分离度 < 阈值（或白斑占比 < 1% / > 90%）时提示"可能无白斑/对比不足"，而不是硬给结果。
- 验收：占比误差中位数 ≤ 8pp、精确率 ≥ 0.7；用户确认前的平均编辑操作数下降 ≥ 50%（埋点）。

### L3 一点即改（替换画笔为主操作）
- 点白斑 → 加区域；点正常皮肤 → 删区域（复用已有 SAM `/refine`，放宽 `boundary_support` 门槛，并支持负点）。
- "找相似"：用户点一个白斑，按该点色素特征在全图传播（v3 已验证可用，单点不稳，作为辅助而非默认）。
- 画笔/橡皮保留为最后手段；"贴合边界"保留。

### L4 专用分割模型（真正的"精准"）
- 架构：沿用已有 5 类 TorchScript 协议（`registry.py` + `inference.py` 已支持），用 SegFormer-B0 或 MobileNetV3-UNet，512px，CPU 推理 < 0.5s（worker 限 2 核/4G 可承受）。
- 数据三路：
  1. 公开数据预训练：Roboflow "lesionvitiligo" 实例分割约 906 张、Kaggle vitiligo 等（**须逐一核实许可证**，仅限允许商用/研究的）。
  2. 自有数据：用户授权（`training_eligible`、consent 已有字段）的确认掩膜；L2 初稿 + 用户确认 = 低成本标注。
  3. 标注员按 `docs/research/2026-10-06-strategy/09-annotator-guideline-v0.1.md` 精标 + 双人复核。
- 训练离线进行（无 GPU：可租云 GPU 数小时，或 CPU 小模型慢训），产物经 `scripts/assessment_benchmark.py` 在患者不跨 split 的测试集上过线后才登记到 registry。
- 验收：测试集 Dice ≥ 0.80 / IoU ≥ 0.70、占比误差 ≤ 5pp、分肤色/部位不劣化；之后 L2 降级为回退。

### L5 纵向一致性（让"变化"可信）
- 同部位前后两次：用人脸/姿态关键点对齐（`vasi_canvas.align_and_calibrate` 现为孤儿，可接上），上次确认掩膜作为先验参考层。
- 变化判定须超过噪声带（同图重复测量 ±5pp），否则显示"基本稳定"，避免把测量噪声当病情变化。

### 基础：拍摄引导 + 金标准基准（与 L1/L2 并行，必须先做）
- 拍摄：取景框（全脸/局部）、避免强逆光/单侧光、关闭美颜滤镜、同一位置同一光源复拍；可选参照贴纸给 cm²。
- 基准集：首批 60~100 张（多用户、多部位、多肤色、含无白斑负样本），双人独立精标，报告人与人一致性；之后所有算法改动必须在该集上出数。

## 5. 里程碑

| 阶段 | 内容 | 估算 | 上线门槛 |
|---|---|---|---|
| M2a | 复核 M1 皮肤回退；建 60~100 张精标基准 + 评测脚本对接 | 1 周（标注人力另计） | 基准一致性报告 |
| M2b | L1 皮肤解析上线（后端 worker），前端不变 | 3~4 天 | 皮肤 IoU ≥0.85 |
| M3 | L2 初稿直写白斑层 + 低置信带 + 自检提示；前端默认"确认" | 1 周 | 误差中位 ≤8pp，编辑次数 −50% |
| M4 | L3 正/负点 SAM 修正、找相似 | 1 周 | 用户完成时长下降 |
| M5 | L4 数据集整理、训练、基准过线、灰度 | 3~6 周（取决于数据） | Dice ≥0.80 |
| M6 | L5 纵向对齐与变化判定 | 1~2 周 | 同图重复差 < 2pp |

## 6. 风险与边界

- RGB 照片对早期、三色、炎症性白斑天然不敏感；产品文案保持"照片内浅色占比"，不宣称临床 VASI。
- 深肤色（V–VI）与极浅肤色（I–II）对比方向/幅度不同，基准必须分层评估。
- 公开数据许可证、用户授权必须合规后才能进入训练。
- 共享后端与 worker 重启影响所有环境；按惯例先测试环境、经确认再上正式。

## 7. 需要拍板

1. 是否批准按 M2a→M2b→M3 顺序推进（L1 皮肤解析需引入 MediaPipe 多类模型文件 16MB）。
2. 金标准标注由谁做（内部标注员 / 合作皮肤科医生），预算多少张。
3. 是否允许下载/使用外部预训练权重与公开数据集（需许可证审查）；是否租用云 GPU 训练 L4。
